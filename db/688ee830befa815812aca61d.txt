<h2>一、 分布式计算概述</h2>
<h3>1. 分布式系统定义</h3>
<blockquote>
<p>分布式系统是由一组通过网络进行通信，为了完成共同的任务而协调工作的计算机节点组成的系统</p>
</blockquote>
<h4>1.1 消息传递模型（Shared-Nothing）</h4>
<ul>
<li>节点之间通过消息传递进行通信</li>
<li>内部运算速度快，但通信速度慢</li>
</ul>
<h4>1.2 分布式计算与并行计算</h4>
<ul>
<li>分布式计算是并行计算的一种特殊形式</li>
<li>并行计算
<ul>
<li>指令并行</li>
<li>CPU多核并行：多线程编程</li>
<li>多CPU并行（一致性内存共享）：多进程编程</li>
<li>多CPU并行（非一致性内存共享）：分布式计算</li>
<li>基于GPU的并行计算</li>
<li>多机并行计算</li>
</ul></li>
</ul>
<h4>1.3 分布式与云计算</h4>
<ul>
<li>
<p>云计算</p>
<ul>
<li>用户角度：是一种服务/应用/交付模式，方便用户随时随地通过网络访问应用程序、存储数据，<strong>不是一种技术</strong></li>
</ul>
</li>
<li>与分布式计算的关系
<ul>
<li>云计算是目标，分布式计算是手段</li>
<li>分布式计算是实现云计算的核心技术之一（还有虚拟化技术，网络通信技术，安全技术等）</li>
</ul></li>
</ul>
<h3>2. 构建分布式系统的收益</h3>
<ul>
<li>提高计算能力</li>
<li>提高存储能力</li>
<li>提高网络吞吐能力</li>
<li>提高可靠性</li>
<li>提高可扩展性</li>
<li>提高安全性</li>
<li>实现资源共享</li>
<li>实现跨时空协同服务</li>
</ul>
<h3>3. 分布式系统衡量指标</h3>
<ul>
<li>业务层性能
<ul>
<li>时间复杂度</li>
<li>空间复杂度</li>
<li>通信复杂度</li>
</ul></li>
<li>可扩展性：系统能够适应业务量的增长</li>
<li>容错性：系统在部分节点失效时，仍能正常工作</li>
<li>并发性：系统能同时处理多个请求</li>
<li>透明性：用户感知不到系统的分布式特性</li>
<li>开放性：节点可以动态加入或退出系统</li>
<li>安全性：系统能抵御各种攻击</li>
<li>可观测/可维护性：系统能够监控自身的运行状态，及时发现故障并修复</li>
</ul>
<blockquote>
<p>简记：扩容，容错，并发，透明，开放，安全，可观测</p>
</blockquote>
<h3>4. 设计分布式系统的挑战</h3>
<p><strong>与性能衡量指标</strong>  类似</p>
<h3>5. 分布式计算任务的分类</h3>
<h4>5.1 OLTP（联机事务处理）</h4>
<p>实时处理大量的短小的事务请求，每个事务请求的处理时间很短，通常是几毫秒到几秒钟</p>
<h4>5.2 OLAP（联机分析处理）</h4>
<p>对大量的历史数据进行分析，通常是对大量数据进行聚合计算，每个计算任务的处理时间很长，通常是几分钟到几小时</p>
<h4>5.3 流式计算</h4>
<p>对大量的实时数据进行分析，通常是对数据进行过滤、聚合、统计等操作，每个计算任务的处理时间很短，通常是几毫秒到几秒钟</p>
<h3>6. 分布式系统架构模式</h3>
<h4>6.1 客户端-服务器模式</h4>
<h5>负载均衡技术</h5>
<ol>
<li>
<p>如何架构</p>
<ul>
<li>通过DNS轮询</li>
<li>通过反向代理</li>
<li>通过负载均衡器</li>
</ul>
</li>
<li>
<p>带来的收益</p>
<ul>
<li>提高系统的可扩展性，弹性增减节点</li>
<li>提高系统的可靠性</li>
<li>提高系统的性能</li>
</ul>
</li>
<li>常用的负载均衡算法及优劣
<ul>
<li>轮询：简单，均衡，但不考虑节点的负载情况</li>
<li>随机：简单，均衡，但不考虑节点的负载情况</li>
<li>最少连接：考虑节点的负载情况，但不考虑节点的性能</li>
<li>最少响应时间：考虑节点的负载情况，考虑节点的性能，但不考虑节点的可用性</li>
<li>哈希：考虑节点的负载情况，考虑节点的性能，考虑节点的可用性，但不支持动态增减节点</li>
<li>一致性哈希：考虑节点的负载情况，考虑节点的性能，考虑节点的可用性，支持动态增减节点</li>
</ul></li>
</ol>
<h4>6.2 主从模式</h4>
<h5>主从模式的概念</h5>
<ul>
<li>
<p>主节点</p>
<blockquote>
<p>负责处理客户端的请求，维护系统的状态</p>
</blockquote>
</li>
<li>
<p>从节点</p>
<blockquote>
<p>负责处理主节点分配的任务，不维护系统的状态</p>
</blockquote>
</li>
</ul>
<h5>主从模式的优缺点</h5>
<ul>
<li>优点
<ul>
<li>提高系统的可扩展性</li>
<li>提高系统的可靠性</li>
<li>提高系统的性能</li>
</ul></li>
<li>缺点
<ul>
<li>主节点成为瓶颈</li>
<li>从节点的状态不一致</li>
</ul></li>
</ul>
<h4>6.3 总线模式</h4>
<h5>总线模式的概念</h5>
<ul>
<li>不同节点通过总线进行通信</li>
<li>消息发送与接受者解耦</li>
<li>异步</li>
<li>分工</li>
</ul>
<h4>6.4 对等模式</h4>
<h5>对等模式的概念</h5>
<ul>
<li>系统中的所有计算节点任务分工都是对等的</li>
<li>完全相同的软件在不同的节点上运行，只是初始化参数不同</li>
</ul>
<h5>对等模式的优缺点</h5>
<ul>
<li>
<p>优点</p>
<ul>
<li>不会出现单点故障</li>
<li>无需维护系统的状态</li>
</ul>
</li>
<li>缺点
<ul>
<li>效率低</li>
</ul></li>
</ul>
<h3>7. 分布式中间件的概念</h3>
<h4>7.1 中间件在计算机系统中的位置</h4>
<blockquote>
<p>中间件是介于操作系统和应用程序之间的软件，它为应用程序提供服务，为操作系统提供接口</p>
</blockquote>
<h4>7.2 中间件的作用</h4>
<ul>
<li>为开发者提供高层的抽象接口</li>
<li>提高互操作性和可移植性</li>
<li>提供分布式系统的基础设施</li>
</ul>
<h4>7.3 中间件的基本表现形式</h4>
<ul>
<li>独立的后台进程</li>
<li>语言编译/解释器的一部分</li>
<li>函数库</li>
</ul>
<h2>二、分布式系统节点通信技术</h2>
<h3>1. 基于Socket的通信技术</h3>
<h4>1.1 Socket的概念</h4>
<ul>
<li>Socket是一种通信机制，它允许不同节点上的应用程序通过网络进行通信</li>
<li>是传输层和网络层提供给应用层的接口</li>
</ul>
<h4>1.2 基于流式Socket（TCP）</h4>
<ol>
<li>建立连接（三次握手）
<ul>
<li>客户端向服务器发送连接请求</li>
<li>服务器向客户端发送连接确认</li>
<li>客户端向服务器发送连接确认</li>
</ul></li>
<li>发送请求
<ul>
<li>客户端向服务器发送请求</li>
</ul></li>
<li>返回响应
<ul>
<li>服务器向客户端发送响应</li>
</ul></li>
<li>关闭连接</li>
</ol>
<h4>1.3 基于数据报Socket（UDP）</h4>
<ol>
<li>发送请求
<ul>
<li>客户端向服务器发送请求</li>
</ul></li>
<li>返回响应
<ul>
<li>服务器向客户端发送响应</li>
</ul></li>
</ol>
<p><strong>与TCP的区别</strong>：没有建立连接的过程，不可靠，不保证数据的顺序</p>
<h4>1.4 并发服务技术</h4>
<ul>
<li>多线程——线程池
<ul>
<li>优点：线程复用，减少线程创建和销毁的开销</li>
</ul></li>
<li>多路复用（事件驱动技术）
<ul>
<li>优点：单线程，减少线程切换的开销，适用于<strong>并发连接数少，连接时间短，IO密集</strong>的场景  </li>
</ul></li>
</ul>
<h3>2. 远程过程调用RPC（上层通信技术）</h3>
<blockquote>
<p>凤凰架构
RPC是一种通信机制，它允许不同节点上的应用程序通过网络进行通信，它是Socket的高级封装，使应用程序可以像调用本地函数一样调用远程函数</p>
</blockquote>
<h4>2.1 RPC的基本原理</h4>
<ol>
<li>序列化/反序列化
<ul>
<li>序列化：将对象转换为字节序列</li>
<li>反序列化：将字节序列转换为对象</li>
</ul></li>
<li>插桩/代理（stub/skeleton）
<ul>
<li>插桩：客户端调用本地函数，插桩将函数调用转换为网络消息</li>
<li>代理：服务器端接收网络消息，代理将网络消息转换为函数调用</li>
</ul></li>
<li>实现RPC语义的应用层协议</li>
<li>负责远程对象的集中注册与管理</li>
</ol>
<h5>点对点通信的缺点</h5>
<ul>
<li>关系复杂，耦合度高</li>
<li>可扩展性差</li>
</ul>
<h4>2.2 RPC中间件的作用——注册中心的作用</h4>
<ul>
<li>服务启动时，将服务的地址注册到注册中心，客户端从注册中心获取服务地址，实现服务发现</li>
<li>优点： 动态增减节点，负载均衡，容错</li>
</ul>
<h4>2.3 接口描述语言IDL</h4>
<ul>
<li>作用：定义接口，实现语言无关，平台无关，网络协议无关</li>
</ul>
<h4>2.4 RPC调用模式</h4>
<ul>
<li>
<p>同步调用</p>
<ul>
<li>客户端调用远程函数，等待远程函数返回结果</li>
</ul>
</li>
<li>异步调用
<ul>
<li>客户端调用远程函数，不等待远程函数返回结果，继续执行后续操作</li>
<li>远程函数执行完毕后，通知客户端</li>
</ul></li>
</ul>
<h3>3. 基于HTTP的通信技术</h3>
<ul>
<li>
<p>Web Service</p>
<ul>
<li>优点：跨平台，跨语言，跨网络</li>
<li>缺点：效率低，不支持异步调用</li>
</ul>
</li>
<li>RESTful
<ul>
<li>优点：效率高，支持异步调用</li>
<li>缺点：不支持跨语言，跨网络</li>
</ul></li>
</ul>
<h3>4. 基于消息队列（MOM）中间件的通信技术</h3>
<ol>
<li>
<p>优势</p>
<ul>
<li>异步通信，提高系统的并发性</li>
<li>解耦，提高系统的可扩展性</li>
<li>削峰填谷，提高系统的可靠性</li>
</ul>
</li>
<li>
<p>通信模式</p>
<ol>
<li>消息队列
<ul>
<li>一对一（一个队列，一个消费者）</li>
<li>一对多（一个队列，多个消费者）</li>
</ul></li>
<li>发布/订阅
<ul>
<li>一对多，广播</li>
</ul></li>
</ol>
</li>
<li>
<p>投递模式</p>
<ul>
<li>
<p>At Most Once</p>
<ul>
<li>消息可能会丢失，但不会重复投递</li>
</ul>
</li>
<li>
<p>At Least Once</p>
<ul>
<li>消息不会丢失，但可能会重复投递</li>
</ul>
</li>
<li>Exactly Once
<ul>
<li>消息不会丢失，不会重复投递</li>
</ul></li>
</ul>
</li>
<li>缓存模式
<ul>
<li>持久化
<ul>
<li>消息持久化到磁盘</li>
</ul></li>
<li>非持久化
<ul>
<li>消息不持久化到磁盘</li>
</ul></li>
</ul></li>
</ol>
<h2>三、 模型问题</h2>
<h3>1. 设计分布式系统的挑战</h3>
<h4>1.1 不可靠的网络——信道故障</h4>
<ul>
<li>传输延迟的不确定性</li>
<li>网络断裂</li>
<li>丢包</li>
<li>乱序</li>
</ul>
<h4>1.2 不可靠的节点</h4>
<ul>
<li>部分节点失效</li>
<li>单点失效</li>
</ul>
<h4>1.3 不可靠的时钟</h4>
<h3>2.分布式系统的模型</h3>
<h4>2.1 节点故障模型</h4>
<ul>
<li>
<p>fail-stop模型</p>
<ul>
<li>节点失效后，不会再次恢复</li>
</ul>
</li>
<li>
<p>fail-stop-restart模型</p>
<ul>
<li>节点失效后，会再次恢复</li>
</ul>
</li>
<li>byzantine模型
<ul>
<li>节点失效后，会再次恢复，但是恢复后的节点可能会发生任意行为</li>
</ul></li>
</ul>
<h4>2.2 链路模型</h4>
<ul>
<li>
<p>任意链路</p>
<ul>
<li>丢包、重复包、内容篡改、伪造、乱序、传输延迟抖动</li>
<li>有主动攻击者存在的情况</li>
</ul>
</li>
<li>
<p>一般损失链路</p>
<ul>
<li>只存在丢包、重复包、乱序和传输延迟抖动</li>
<li>链路会发生断裂（Partition），但断裂持续时间是有限的</li>
</ul>
</li>
<li>
<p>可靠链路</p>
<ul>
<li>发送者发出的每个消息都可以被正确接收</li>
<li>但是：</li>
<li>存在传输延迟抖动</li>
<li>接收到消息的顺序可能和发送顺序不一致</li>
</ul>
</li>
<li>
<p>可靠FIFO链路</p>
<ul>
<li>发出的每个消息都可以被正确接收并且不会乱序</li>
</ul>
</li>
<li>如何基于弱假设链路实现强假设链路
<ul>
<li>如何基于“任意链路” 实现“一般损失链路”？</li>
<li>利用纠错码、HASH函数、消息认证码、加密算法等手段；</li>
<li>利用SSL/TLS/HTTPS协议</li>
<li>如何基于“一般损失链路” 实现“可靠链路”？</li>
<li>发送者持续地尝试重传数据包，直到收到ACK；</li>
<li>利用数据包序列号等手段实现去除重复数据包</li>
<li>如何基于“可靠链路”实现“可靠FIFO链路”？</li>
<li>利用数据包序列号，对收到的数据包进行排序，然后按序列号由小到大依次向应用层投递</li>
</ul></li>
</ul>
<h4>2.3 时间同步模式</h4>
<ul>
<li>
<p>同步模式</p>
<ul>
<li>消息传输延迟不超过已知的上限</li>
<li>节点以已知速度执行算法</li>
</ul>
</li>
<li>
<p>异步模式</p>
<ul>
<li>消息传输延迟没有上限</li>
<li>节点在运行期间可能会暂停任意长的时间</li>
</ul>
</li>
<li>部分同步模式
<ul>
<li>系统大部分时间工作在同步模式；</li>
<li>但在有限时间段（该时间段长度不可预知）内工作在异步
模式；</li>
</ul></li>
</ul>
<h2>四、 时钟问题</h2>
<h3>1. 物理时钟</h3>
<h4>1.1 单调钟的概念</h4>
<ul>
<li>按照一定频率持续自增；</li>
<li>其绝对值无意义，相对值表示延时或时间差；</li>
<li>Java：System.nanoTime()</li>
</ul>
<h4>1.2 墙钟的概念</h4>
<ul>
<li>和日常生活中的日历、天文事件对应的时钟</li>
<li>世界墙钟标准：协调世界时（Coordinated Universal Time）</li>
<li>可能会发生倒流现象（NTP时钟校正、闰秒）</li>
<li>System.currentTimeMillis() （1970-1-1 午夜 0点以来的秒数</li>
</ul>
<h4>1.3 NTP实现时钟同步的原理</h4>
<ul>
<li>
<p>Cristian算法</p>
<ul>
<li>
<p>客户端发送请求包，以其本地时钟<katex-inline>T_1</katex-inline>为时间戳</p>
</li>
<li>
<p>服务器在收到请求<katex-inline>T_2</katex-inline>及其本地时钟</p>
</li>
<li>
<p>服务器发送一个带有其本地时钟<katex-inline>T_3</katex-inline>和<katex-inline>T_2</katex-inline>的包</p>
</li>
<li>
<p>客户端在本地对其接收服务器响应的时间戳T4<katex-inline>T_4</katex-inline></p>
</li>
<li>目标：将时钟校正为</li>
</ul>
<p><katex-inline>T_3 + ?_{resp}</katex-inline></p>
<p><katex-inline>?_{resp} = \frac{(T_2 - T_1) + (T_3 - T_4)}{2}</katex-inline></p>
</li>
</ul>
<h3>2. 逻辑时钟</h3>
<h4>2.1 Lamport时钟</h4>
<ol>
<li>
<p>Happen-Before关系</p>
<ul>
<li>
<p>如果事件<katex-inline>a</katex-inline>和<katex-inline>b</katex-inline>是同一个节点（单进程/线程）中的两个事件,事件<katex-inline>a</katex-inline>发生在事件<katex-inline>b</katex-inline>之前，那么<katex-inline>a \to b</katex-inline></p>
</li>
<li>
<p>如果<katex-inline>a</katex-inline>事件是 “节点<katex-inline>P_1</katex-inline>发送消息<katex-inline>m</katex-inline>到<katex-inline>P_2</katex-inline>”，<katex-inline>b</katex-inline>事件是“节点<katex-inline>P_2</katex-inline>接收消息<katex-inline>m</katex-inline>”，那么<katex-inline>a \to b</katex-inline></p>
</li>
<li>
<p>如果<katex-inline>a \to b</katex-inline>且<katex-inline>b \to c</katex-inline>，那么<katex-inline>a \to c</katex-inline>(传递性)</p>
</li>
<li>如果<katex-inline>a ↛ b</katex-inline>且<katex-inline>b ↛ a</katex-inline>，那么<katex-inline>a</katex-inline>和<katex-inline>b</katex-inline>是并发事件</li>
</ul>
</li>
<li>
<p>Lamport时钟</p>
<ul>
<li>每个节点维护一个逻辑时钟，初始值为<katex-inline>C_i</katex-inline></li>
<li>每个节点在执行一个事件生（消息产生、消息发送、消息接收都是事件）时，将逻辑时钟加1</li>
<li>每个节点在发送消息时，将逻辑时钟加1，并将当前逻辑时钟作为消息的时间戳</li>
<li>每个节点在接收消息时，将逻辑时钟更新为“当前逻辑时钟”和“消息时间戳”中较大的值加1</li>
</ul>
</li>
</ol>
<h4>2.2 向量逻辑时钟</h4>
<ol>
<li>基本算法</li>
</ol>
<ul>
<li>
<p>设分布式系统包含 n 个节点<katex-inline>N_1,N_2,...,N_n</katex-inline>，节点<katex-inline>N_i</katex-inline>的向量时钟<katex-inline>T</katex-inline>形式为：</p>
<p><katex-inline>T = (T_1,T_2,...,T_n)</katex-inline></p>
<p>其中<katex-inline>T[i] = T_j</katex-inline>表示节点<katex-inline>N_i</katex-inline>的逻辑时钟,<katex-inline>T[j]</katex-inline>表示<katex-inline>N_i</katex-inline>所知道的关于节点<katex-inline>N_j</katex-inline>的最大标量时钟值</p>
</li>
<li>
<p>向量时钟的更新</p>
<ul>
<li>节点<katex-inline>N_i</katex-inline>在执行一个事件时，将自己的标量时钟自增；</li>
<li>节点<katex-inline>N_i</katex-inline>在发送消息时，将当前向量时钟<katex-inline>T</katex-inline>作为消息的时间戳；</li>
<li>当收到其它节点发送的消息<katex-inline>&lt;m,T_m&gt;</katex-inline>时，节点<katex-inline>N_i</katex-inline>将自己的向量时钟<katex-inline>T</katex-inline>更新为：
<katex-inline>T[j] = max(T[j],T_m[j])</katex-inline>
<katex-inline>T[i] = T[i] + 1</katex-inline></li>
</ul>
</li>
</ul>
<ol start="2">
<li>优缺点</li>
</ol>
<ul>
<li>
<p>优点</p>
<ul>
<li><strong>可以检测出因果关系</strong></li>
</ul>
</li>
<li>缺点
<ul>
<li>向量时钟的长度随节点数目增加而增加，不适合大规模系统</li>
</ul></li>
</ul>
<h4>2.3 向量时钟的应用</h4>
<ol>
<li>
<p>全序广播</p>
</li>
<li>因果排序广播</li>
</ol>
<h2>五、 分布式存储</h2>
<h3>1. 复制（多副本）技术</h3>
<h4>1.1 多副本复制带来的收益和挑战</h4>
<ul>
<li>收益
<ul>
<li>提供冗余</li>
<li>应对节点失效</li>
<li>提高吞吐率</li>
<li>改善访问性能</li>
</ul></li>
<li>挑战
<ul>
<li>硬件成本</li>
<li>保持一致性困难</li>
</ul></li>
</ul>
<h4>1.2 主从技术复制</h4>
<ul>
<li>
<p>单主复制</p>
<blockquote>
<p>一个领导者，多个从属者</p>
<p>优点：简单</p>
<p>缺点：主节点成为瓶颈</p>
</blockquote>
<ul>
<li>同步复制:
领导者将每个写操作发送给所有从属者，直到所有从属者都确认写操作后，领导者才能确认写操作</li>
<li>异步复制：
领导者将每个写操作发送给所有从属者，但不等待从属者确认写操作，而是立即确认写操作</li>
<li>链式复制：
从属者将写操作发送给其他从属者，而不是领导者，形成一个链式结构</li>
<li>混合复制：
部分从属者采用同步复制，部分从属者采用异步复制</li>
</ul>
</li>
<li>
<p>多主复制</p>
</li>
<li>无主复制</li>
</ul>
<h3>2. 分布式系统一致性模型</h3>
<h4>2.1 一致性模型的概念</h4>
<p>多个客户端同时访问分布式系统，系统应该保证客户端看到的数据是一致的</p>
<h4>2.2 强一致性（线性一致性）</h4>
<p>分布式系统对外提供的服务，与单机系统对外提供的服务一致，即客户端看到的对系统的操作是与物理世界真实发生的顺序一致的</p>
<h4>2.3 最终一致性和弱一致性</h4>
<ul>
<li>
<p>最终一致性</p>
<ul>
<li>系统保证在没有新的更新操作时，系统最终会达到一致状态</li>
<li>适用于读操作远远多于写操作的场景</li>
</ul>
</li>
<li>弱一致性
<ul>
<li>系统不保证在没有新的更新操作时，系统最终会达到一致状态</li>
<li>适用于读操作远远多于写操作的场景</li>
</ul></li>
</ul>
<h4>2.4 CAP定理</h4>
<blockquote>
<p>CAP定理指出，对于一个分布式系统来说，不可能同时满足以下三点,最多只能同时满足两点</p>
</blockquote>
<ul>
<li>
<p>一致性（Consistency）</p>
<ul>
<li>所有节点在同一时间具有相同的数据</li>
</ul>
</li>
<li>
<p>可用性（Availability）</p>
<ul>
<li>保证每个请求不管成功或者失败都有响应</li>
</ul>
</li>
<li>割舍分区容错性（Partition tolerance）
<ul>
<li>系统中任意信息的丢失或失败不会影响系统的继续运作</li>
</ul></li>
</ul>
<h3>3. 分布式共识协议</h3>
<h4>3.1 共识协议的作用</h4>
<blockquote>
<p>利用共识协议，分布式系统可以在不同节点之间达成一致，从而保证分布式系统的一致性</p>
</blockquote>
<ul>
<li>多副本主从复制</li>
<li>异步通信</li>
<li>容错</li>
</ul>
<h4>3.2 复制状态机的概念</h4>
<ul>
<li>状态机</li>
</ul>
<blockquote>
<p>状态机是一个抽象的数学模型，它包含一组状态和一组操作，每个操作都将状态从一个状态转换为另一个状态</p>
</blockquote>
<ul>
<li>目标：让所有节点的状态机保持一致</li>
<li>用处：某节点的状态机失效，可立即切换到另一个节点的状态机</li>
<li>实现：
<ul>
<li>每个节点维护一个日志，日志中记录了所有状态机执行的操作</li>
<li>利用共识协议，让所有节点的日志保持一致</li>
</ul></li>
</ul>
<h4>3.3 共识协议和分布式一致性的关系</h4>
<ul>
<li>共识协议是分布式一致性的基础</li>
<li>一致性是对用户的承诺</li>
<li>共识协议是实现一致性的手段</li>
</ul>
<h4>3.4 按容错模型分类</h4>
<ol>
<li>
<p>失效停止模式共识协议</p>
<blockquote>
<p>最多允许f = (n-1)/2个节点失效</p>
</blockquote>
<ul>
<li>Paxos</li>
<li>
<p><strong>Raft</strong></p>
<ul>
<li>
<p>过程：</p>
<ol>
<li>Leader接收客户端请求，存入日志</li>
<li>将新增日志复制给其他节点</li>
<li>确认日志复制成功，提交日志，执行日志中的命令</li>
</ol>
</li>
<li>Leader选举过程：
<ol>
<li>Leader失效</li>
<li>Follower发现Leader失效，发起选举</li>
<li>超过半数节点投票给某个Follower，该Follower成为新的Leader</li>
<li>修改朝代号，通知其他节点</li>
</ol></li>
</ul>
</li>
<li>Zab</li>
</ul>
</li>
<li>
<p>拜占庭模式共识协议</p>
<blockquote>
<p>原理：通过多数派原则，保证系统的一致性</p>
</blockquote>
<ul>
<li>PBFT</li>
<li>VFT</li>
</ul>
</li>
</ol>
<h3>4. 分区（分片）技术</h3>
<h4>4.1 分区带来的收益和挑战</h4>
<ul>
<li>
<p>收益</p>
<ul>
<li>提高系统的可扩展性</li>
<li>提高系统的可靠性</li>
<li>提高系统的性能</li>
</ul>
</li>
<li>挑战
<ul>
<li>数据分布不均匀</li>
<li>跨分区查询</li>
<li>事务处理</li>
</ul></li>
</ul>
<h4>4.2 分区技术的分类</h4>
<ol>
<li>
<p>按主键范围分区</p>
<blockquote>
<p>将主键的值按范围划分到不同的分区</p>
</blockquote>
<ul>
<li>
<p>均匀分区</p>
<blockquote>
<p>将主键的值按范围均匀划分到不同的分区</p>
</blockquote>
<ul>
<li>优点：容易实现点查询，范围查询，排序等操作</li>
<li>缺点：不适合数据分布不均匀的场景</li>
</ul>
</li>
<li>
<p>不均匀分区</p>
<blockquote>
<p>将主键的值按范围不均匀划分到不同的分区</p>
</blockquote>
<ul>
<li>优点：可处理数据偏斜，热点查询</li>
<li>缺点：需要全局索引，导致查询多了一次网络开销</li>
</ul>
</li>
</ul>
</li>
<li>
<p>哈希分区</p>
<blockquote>
<p>确定性，随机性，无碰撞性</p>
</blockquote>
<ul>
<li>
<p>简单哈希分区</p>
<blockquote>
<p>将主键的值通过哈希函数计算，得到哈希值，再通过哈希值对分区数取模，得到分区号</p>
</blockquote>
</li>
<li>
<p>一致性哈希分区</p>
<blockquote>
<p>将主键的值通过哈希函数计算，得到哈希值，再通过哈希值对分区数取模，得到分区号</p>
</blockquote>
</li>
<li>
<p>优点：</p>
<ul>
<li>可处理数据分布不均匀，热点查询；</li>
<li>不用全局索引，减少网络开销</li>
<li>不用事先知道数据分布情况</li>
</ul>
</li>
<li>
<p>缺点：</p>
<ul>
<li>效率低，需要多次哈希计算</li>
<li>在分区数变化时，数据迁移量大</li>
<li>物理储存少时容易出现偏斜和热点问题</li>
</ul>
</li>
</ul>
</li>
</ol>
<h4>4.3 分区技术带来的挑战</h4>
<ul>
<li>
<p>分布式事务概念(ACID)</p>
<ul>
<li>原子性（Atomicity）</li>
</ul>
<blockquote>
<p>事务是一个不可分割的工作单位，事务中的操作要么全部成功，要么全部失败</p>
</blockquote>
<ul>
<li>一致性（Consistency）</li>
</ul>
<blockquote>
<p>事务执行前后，系统的状态保持一致</p>
</blockquote>
<ul>
<li>隔离性（Isolation）</li>
</ul>
<blockquote>
<p>事务的执行不会相互影响</p>
</blockquote>
<ul>
<li>持久性（Durability）</li>
</ul>
<blockquote>
<p>事务执行成功后，对系统的影响是永久的</p>
</blockquote>
</li>
</ul>
<h4>4.4 分区和复制组和使用</h4>
<ul>
<li>节点内有多个分区，每个分区有多个副本</li>
<li>每个节点充当某些分区的领导者，其他分区充当从属者</li>
</ul>
<h4>4.5 HDFS分布式文件系统</h4>
<ol>
<li>
<p>HDFS系统架构</p>
<ul>
<li>
<p>NameNode(主节点)</p>
<blockquote>
<p>负责管理文件系统的命名空间，维护文件系统的元数据</p>
</blockquote>
</li>
<li>
<p>DataNode(从节点)</p>
<blockquote>
<p>负责管理文件系统的数据块，维护文件系统的数据块副本</p>
</blockquote>
</li>
</ul>
</li>
<li>
<p>HDFS工作机制</p>
<ul>
<li><strong>读操作</strong>
<ul>
<li>客户端向NameNode发送读请求，</li>
<li>NameNode返回数据块所在的DataNode列表</li>
<li>客户端直接从<strong>最近的</strong>DataNode读取数据</li>
</ul></li>
<li>
<p><strong>写操作</strong></p>
<ul>
<li>客户端向NameNode发送写请求</li>
<li>NameNode根据负载均衡策略，返回数据块所在的DataNode列表，共3个</li>
<li>客户端将3个数据节点构成一个流水线，将第一个数据块写入流水线</li>
<li>再向NameNode获取下一个数据块对应的3个DataNode列表</li>
</ul>
</li>
<li>数据复制方法</li>
</ul>
</li>
</ol>
