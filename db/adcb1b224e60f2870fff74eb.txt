<h1 id="0x00-elf文件入门">0x00 ELF文件入门
</h1><p><strong>ELF</strong>（<code>Executable and Linkable Format</code>）是一种<em><strong>可执行</strong></em>和<em><strong>可链接</strong></em>的文件格式，是linux底下二进制文件，可以理解为windows下的<code>PE文件</code>，在Android中可以比作<code>SO</code>，方便函数的移植，在常用于保护Android软件，增加逆向难度。其核心价值在于支持程序的<strong>执行</strong>（如二进制程序运行、动态库加载）和<strong>链接</strong>（编译过程中的模块组合），是跨平台二进制兼容的基础。</p>
<p><strong>ELF文件的主要组成部分包括：</strong></p>
<ul>
<li>
<p><code>ELF Header</code>：文件头，描述文件的基本信息</p>
</li>
<li>
<p><code>Program Header Table</code>：程序头表，描述进程映像的布局</p>
</li>
<li>
<p><code>Section Header Table</code>：节区头表，描述文件的各个节区</p>
</li>
<li>
<p>程序头表与分段头表引用的数据，比如 .text .data。</p>
<p><img src="https://ctf-wiki.org/executable/elf/structure/figure/object_file_format.png"
	
	
	
	loading="lazy"
	
	
></p>
</li>
</ul>

<h2 id="program-header-table程序头表">Program Header Table（程序头表）
</h2><p><strong>Program Header Table</strong> 是一个结构体数组，每一个元素的类型是 <code>Elf32_Phdr</code>，描述了一个段或者其它系统在准备程序执行时所需要的信息。</p>
<p>其中，ELF 头中的 <code>e_phentsize</code> 和 <code>e_phnum</code> 指定了该数组每个元素的大小以及元素个数。一个目标文件的段包含一个或者多个节。<strong>程序的头部只有对于可执行文件和共享目标文件有意义。</strong></p>
<p>可以说，<strong>Program Header Table</strong> 就是专门为 ELF 文件运行时中的段所准备的。</p>

<p><strong>核心意义</strong>：操作系统加载 ELF 文件时，根据程序头表将 &ldquo;段&rdquo; 映射到内存，例如：</p>
<ul>
<li><code>p_type=PT_LOAD</code>的段会被加载到<code>p_vaddr</code>指定的内存地址。</li>
<li><code>p_flags=0x5</code>（R+X）通常对应代码段（可执行且只读），<code>p_flags=0x6</code>（R+W）对应数据段。</li>
</ul>

<p><strong>段与节区的关系</strong></p>
<ul>
<li><strong>段（Segment）</strong>：面向运行时，由一个或多个节区组成（如<code>.text</code>和<code>.rodata</code>可合并为一个 &ldquo;代码段&rdquo;）。</li>
<li><strong>节区（Section）</strong>：面向编译时，按功能划分的最小数据单元。</li>
</ul>
<p>例如：一个<code>PT_LOAD</code>段可能包含<code>.text</code>（代码）和<code>.rodata</code>（只读数据）两个节区，共同映射到内存的只读可执行区域。</p>

<h1 id="0x01-arm基础知识">0x01 ARM基础知识
</h1><ul>
<li>
<p>&ldquo;<strong>x86、arm、RISC-V</strong>&rdquo; 都是 <strong>指令集架构 ( CPU架构 )</strong>。ARM 是主流的 RISC（精简指令集）架构，广泛用于嵌入式设备（如 Android 手机）。</p>
</li>
<li>
<p><strong>指令集特点</strong></p>
</li>
<li>
<p>固定指令长度（32 位 ARM 指令，Thumb 模式为 16 位）。</p>
</li>
<li>
<p>大部分指令可条件执行（如<code>ADDNE R0, R1, R2</code>：仅当标志位不为 0 时执行加法）。</p>
</li>
<li>
<p>寄存器操作优先（算术 / 逻辑运算通常基于寄存器，内存访问需专用指令）。</p>
</li>
<li>
<p><strong>核心寄存器</strong></p>
</li>
</ul>
<p>​	ARM32 架构有 16 个通用寄存器（<code>R0-R15</code>），其中：</p>
<ul>
<li><code>R0-R3</code>：函数调用参数 / 返回值寄存器。</li>
<li><code>R4-R11</code>：通用寄存器（需手动保存）。</li>
<li><code>R12</code>（IP）：临时寄存器。</li>
<li><code>R13</code>（SP）：栈指针寄存器（指向栈顶）。</li>
<li><code>R14</code>（LR）：链接寄存器（存储函数返回地址）。</li>
<li><code>R15</code>（PC）：程序计数器（存储下一条执行的指令地址）。</li>
</ul>

<h1 id="0x02-android-so文件分析">0x02 Android so文件分析
</h1><h2 id="1so-文件概述">1.SO 文件概述
</h2><ul>
<li>
<p><strong>SO</strong> 文件是 Unix/Linux 系统中的动态库文件，被称为共享目标文件（<strong>Shared Object File</strong>），后缀名为 <code>.so</code>，它是 ELF 的一种，另外属于 <strong>ELF</strong> 类型的还有可重定位文件（Relocatable File）以及核心转储文件（Core Dump File）。</p>
</li>
<li>
<p>SO 文件通常用于提高开发效率、方便快速移植代码，以及保护 Android 应用的核心逻辑，增加逆向工程的难度。不同的 CPU 架构（如 ARM、x86 等）需要不同版本的 SO 文件来适配其指令集和运行环境。</p>
</li>
</ul>

  <thead>
      <tr>

          <th>与 ARM 的关联</th>
      </tr>
  </thead>

      <tr>

          <td>ARM32/64 位设备的可执行文件需对应架构</td>
      </tr>
      <tr>
          <td>共享目标文件（SO）</td>

<h2 id="3so-文件的加载流程">3.SO 文件的加载流程
</h2><h3 id="loadlibrary-加载流程">loadLibrary 加载流程
</h3><ul>
<li>调用 <code>System.loadLibrary(String libName)</code> 时，实际上会调用 <code>Runtime.getRuntime().loadLibrary(String libName)</code>。</li>
<li><code>Runtime.loadLibrary(String libName)</code> 会进一步调用 <code>Runtime.loadLibrary(String libName, ClassLoader loader)</code>，其中 <code>loader</code> 是当前线程的类加载器。</li>
<li>通过类加载器找到对应的 SO 文件路径，然后调用 <code>doLoad(String name, ClassLoader loader)</code> 方法进行加载。</li>
</ul>
<h3 id="load-加载流程">load 加载流程
</h3><ul>
<li>调用 <code>System.load(String pathName)</code> 时，实际上会调用 <code>Runtime.getRuntime().load(String pathName)</code>。</li>
<li><code>Runtime.load(String pathName)</code> 会调用 <code>Runtime.load(String pathName, ClassLoader loader)</code>，同样会调用 <code>doLoad(String name, ClassLoader loader)</code> 方法进行加载。</li>
</ul>
<h3 id="核心加载流程doload">核心加载流程：doLoad
</h3><ul>
<li><strong>路径处理</strong>：<code>doLoad</code> 方法会根据传入的路径和类加载器，确定 SO 文件的实际路径。</li>
<li><strong>动态链接库加载</strong>：调用 <code>dlopen</code> 函数加载动态链接库。</li>
<li><strong>JNI_OnLoad 调用</strong>：如果 SO 文件中定义了 <code>JNI_OnLoad</code> 函数，则在加载完成后调用该函数进行初始化。</li>
</ul>
