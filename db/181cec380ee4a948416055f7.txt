<h1 id="基于-DX12-实现-ShaderLab">基于 DX12 实现 ShaderLab<a class="headerlink" href="#基于-DX12-实现-ShaderLab" title="Permanent link">&para;</a></h1>
<p>ShaderLab 是对 <code>ID3D12RootSignature</code> 和 <code>ID3D12PipelineState</code> 的封装。每次写完 Shader 就会自动生成 <code>RootSignature</code> 和 <code>PipelineState</code>，不用再人工填写那一坨参数。</p>
<!-- more -->

<p>大体设计如下，成员就不写了。</p>
<pre class="mermaid"><code>classDiagram
    Shader --&gt; ShaderKeywordSpace
    Shader --&gt; "many" ShaderProperty : Contains
    Shader --&gt; "many" ShaderPass : Contains
    ShaderPass --&gt; ShaderPassRenderState
    ShaderPass --&gt; "many" ShaderProgram : Contains
    ShaderProgram --&gt; ShaderKeywordSet

    class Shader
    class ShaderProperty
    class ShaderPass
    class ShaderPassRenderState
    class ShaderProgram
    class ShaderKeywordSpace
    class ShaderKeywordSet</code></pre>
<h2 id="编译器">编译器<a class="headerlink" href="#编译器" title="Permanent link">&para;</a></h2>

<p>然后，对不同的 Keyword 组合各进行一次编译。显然，随着 Keyword 数量增加，编译出来的体积会指数爆炸，对运行时的性能也会有更大的影响。Unity 的文档中有相对详细的说明：</p>
<blockquote>
<p>Unity can use up to 4,294,967,294 global shader keywords. Individual shaders and compute shaders can use up to 65,534 local shader keywords. These totals include keywords used for variants, and keywords used for dynamic branching.</p>
<p>Every keyword declared in the shader source file and its dependencies count towards this limit. Dependencies include <a href="https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Pass.html">Passes</a> that the shader includes with <a href="https://docs.unity3d.com/6000.0/Documentation/Manual/SL-UsePass.html">UsePass</a>, and <a href="https://docs.unity3d.com/6000.0/Documentation/Manual/SL-Fallback.html">fallbacks</a>.</p>
<p>If Unity encounters a shader keyword with the same name multiple times, it only counts towards the limit once.</p>
<p><mark>If a shader uses more than 128 keywords in total, it incurs a small runtime performance penalty</mark>; therefore, it is best to keep the number of keywords low. Unity always reserves 4 keywords per shader. <sup id="fnref:1"><a class="footnote-ref" href="#fn:1">1</a></sup></p>
</blockquote>
<p>为了方便实现，我将引擎的 Keyword 数量上限定为 128，这样使用 <code>std::bitset&lt;128&gt;</code> 保存 Keyword 组合就行了。128 位相当于一个 <code>Vector4</code> 的大小，是可以接受的。</p>

<details class="note">
<summary>关于 Hash Collision</summary>
<p>
Hash collisions are to be expected, and they indicate a duplicate object. We avoid duplication by checking an STL map for pre-existing hash values. (Essentially a hash map.) Unexpected collisions (where two completely different series of bytes yield the same hash value), on the other hand, should be so exceedingly rare as to probably never be noticed. If unexpected collisions do arise, I'd suspect you have a different bug (such as in the hashing system itself.) <sup id="fnref:2"><a class="footnote-ref" href="#fn:2">2</a></sup></p>

<p>最后，把参数拼起来就能创建 <code>ID3D12PipelineState</code>。<code>PipelineState</code> 涉及非常多参数，包括编译后的 Shader 指令，不同 Shader 很难复用同一个对象（要是能复用，为什么分成两个 Shader 呢？），所以我把结果根据 Hash 缓存在 <code>ShaderPass</code> 中，有几点好处</p>
<ul>
<li>不同 Shader 的 <code>PipelineState</code> 分开存，能进一步减少 Hash Collision 的可能性</li>
<li>当 Shader 被卸载时，相关的 <code>PipelineState</code> 也会被自动回收</li>
</ul>
