<h2>一、概述</h2>
<h3>1.【重点】基本概念</h3>
<ol>
<li><strong>CIA(机密性、完整性和可用性)</strong></li>
</ol>
<ul>
<li><strong>机密性 Confidentiality</strong>：避免信息的<strong>非授权泄露</strong>
<ul>
<li>加密(Encryption)</li>
<li>访问控制(Access control)</li>
<li>认证(Authentication)</li>
<li>授权(Authorization)</li>
<li>物理安全(Physical security)</li>
</ul></li>
<li><strong>完整性 Integrity</strong>：确保信息不被<strong>非授权修改</strong>的属性
<ul>
<li>备份(Backup)：定期归档</li>
<li>数据校验和(Checksum)：计算一个函数将文件内容映射为一个数值。</li>
<li>数据纠错码(data correcting codes)：检测并纠正数据</li>
<li>保护元数据(metadata)：描述数据的数据。</li>
</ul></li>
<li><strong>可用性 Availability</strong>：确保<strong>授权用户</strong>能够对信息进行<strong>及时访问和修改</strong>的属性（目标用户能使用权限）
<ul>
<li>物理保护：在物理环境恶劣变化时也能够保护信息的可用性。。</li>
<li>计算冗余：在部分计算机或者存储设备失效的情况下依然可以提供信息。例如采用磁盘冗余阵列(RAID)和多台计算机。</li>
</ul></li>
</ul>
<ol start="2">
<li><strong>3A(保证，真实性，匿名性)</strong></li>
</ol>
<ul>
<li>
<p><strong>Assurance 保证</strong>：指计算机系统中<strong>信任</strong> <em>（个人理解为权限及其分配问题）</em>如何被提供和管理</p>
<blockquote>
<p>系统资源的管理和保护：确保系统资源如何在设定策略下使用</p>
<p>信息使用方式的管理：确保信息如何在设定策略下使用</p>
</blockquote>
<p><strong>信任管理：</strong></p>
<ul>
<li>策略(policy)： 指人或者系统对他们或者其他个体的行为预期</li>
<li>权限(permission)： 指在与人和系统交互时所允许的行为</li>
<li>保护(protection)： 指为了实施权限和策略所提供的机制</li>
<li>例子：在线音乐系统(为用户如何访问歌曲设定策略；为购买特定歌曲的用户提供访问权限；为系统提供保护以防止用户未授权的访问)</li>
</ul>
</li>
<li>
<p><strong>Authenticity 真实性</strong>：确定人或者系统所发布的声明、策略和权限真实性的能力</p>
<blockquote>
<p>真实性的满足能够确保在线交易的可行性。</p>
<p><strong>不可抵赖性(Nonrepudiation)</strong>：一个人或者系统不能否认其所发布的真实声明</p>
</blockquote>
<p><strong>主要工具：</strong></p>
<ul>
<li><strong>数字签名(digital signatures)</strong>： 一种加密计算方法，允许人或者系统以唯一的方式认可与其相关数据的真实性。数字签名可实现不可抵赖性。</li>
<li>与纸质签名类比</li>
</ul>
<blockquote>
<p><strong>原题关注</strong>：数字签名为确保真实性工具</p>
</blockquote>
</li>
<li>
<p><strong>Anonymity 匿名性</strong>：确保特定的记录或者交易<strong>不归因于任何个体</strong>的属性。</p>
<blockquote>
<p>不希望隐私泄露，如个体的医疗记录、购物记录等</p>
</blockquote>
<p><strong>确保匿名性的方法：</strong></p>
<ul>
<li>数据聚集(Aggregation)</li>
<li>数据混淆(Mixing)</li>
<li>使用代理(Proxy) <em>(笑死)</em></li>
<li>使用化名(Pseudonym)</li>
</ul>
</li>
</ul>

<h3>3.  【重点】四种控制访问模型</h3>
<ol>
<li>
<p><strong>访问控制矩阵</strong>：定义访问权限的表。</p>
<ul>
<li>优点：
<ul>
<li>很容易确定主客体对的访问控制权限；</li>
<li>管理者能够简单、直观地观察访问控制；</li>
<li>关系控制粒度细。</li>
</ul></li>
<li>缺点：
<ul>
<li>缺乏可扩展性，访问控制矩阵有可能会很大。</li>
</ul></li>
</ul>
<blockquote>
<p>个人总结：详尽但是体积庞杂</p>
</blockquote>
</li>
<li>
<p><strong>访问控制列表</strong>：对于每个客体o，定义列表L， L为客体o的访问控制列表，该列表列举了所有对客体o有访问权限的主体。</p>
<ul>
<li>
<p>优点：</p>
<ul>
<li>与访问控制矩阵比<strong>小很多</strong>，可将客体的列表以元数据形式存储。</li>
</ul>
</li>
<li>缺点：
<ul>
<li>枚举每个主体的访问权限复杂度高。这种枚举是必须的，例如将一个主体从系统中移除的时候。</li>
</ul></li>
</ul>
<blockquote>
<p>个人总结：精炼但关系复杂</p>
</blockquote>

</li>
</ol>

<ol start="3">
<li>
<p><strong>能力列表</strong>：本质上，能力列表使用访问控制矩阵的每一行并忽略其空白单元格。</p>
<ul>
<li>优缺点与访问控制列表类似。</li>
</ul>
</li>
<li>
<p><strong>基于角色的访问控制</strong>：定义角色，并对角色指派访问控制权限，而不是直接对主体。</p>
<ul>
<li>
<p>优点：</p>
<ul>
<li>存储高效，降低需要记录的规则数量</li>
</ul>

<li>在目前操作系统中未实现。</li>
</ul></li>

<h3>3. 【重点】加密概念</h3>
<ol>
<li>
<p><strong>加密(Encryption)</strong>：一种手段使得通信双方(Alice和Bob)在易受窃听的不安全信道上建立保密通信。</p>
<blockquote>
<p>比如两方通信经过加密解密算法，关键词：对称与非对称加密，公钥私钥</p>
</blockquote>
</li>
<li>
<p><strong>数字签名(Digital Signatures)</strong>：公钥加密体制可以用来构造数字签名。</p>
</li>
<li>
<p><strong>密码学哈希函数(Cryptographic Hash Function)</strong>：消息M的一个校验和，需要满足单向性和抗碰撞性。</p>
</li>
<li>
<p><strong>消息认证码(Message Authentication Codes)</strong>：共享密钥，A发送消息与其哈希值，B收到消息再本地验证所收到消息的哈希值。</p>
</li>
<li><strong>数字证书</strong>：比如https，可信机构对网站颁布证书</li>
</ol>

</li>
<li>

</blockquote>
</li>

<h3>2. <strong>【重点】内存与文件系统安全</strong></h3>
<ol>
<li>
<p>内存安全</p>
<ul>
<li>五段内存区中，每一段都有自己的访问权限，由操作系统执行这些权限；</li>
<li>对操作系统安全至关重要：不允许进程访问其他进程的地址空间；</li>
<li>加强地址空间边界保护；</li>
<li>操作系统一般将地址空间分为两个区：用户空间和内核空间。内核空间是为操作系统内核功能保留的特殊空间，有着最为严格的访问特权。</li>
</ul>
</li>
<li>
<p>虚拟内存安全</p>
<ul>
<li>
<p>Windows系统中，虚拟内存页面存储在C:\pagefile.sys中</p>
</li>
<li>
<p>Linux系统需用户自己设定一个硬盘分区作为交换分区，存储内存页面</p>
</li>
<li>
<p>关闭计算机时，硬盘上的虚拟内存页面会被删除</p>
</li>
<li>
<p>虚拟内存安全问题：如果攻击者突然将计算机断电，没有正常关闭计算机，此时虚拟内存页面可能未被删除攻击者通过外部介质引导另一个操作系统，能够查看这些文件并重建部分内存，导致信息泄露</p>
<p>解决办法：对硬盘内容进行加密</p>
</li>
</ul>
</li>
<li>
<p>认证</p>
<ul>
<li>通过身份验证</li>
<li>防范字典攻击：使用<strong>密码盐(password salt)技术</strong>：它是一种加密技术，使用随即位作为散列函数或加密算法的部分输入，从而增加输出的随机性</li>
</ul>
</li>
<li>
<p>文件权限</p>
<ul>
<li>Linux的权限控制</li>
<li>Windows的傻逼权限设计</li>
</ul>
</li>
<li>
<p>文件描述符</p>
<ul>
<li>存储在文件描述符表中的索引值，用来索引特定文件</li>
<li>漏洞：当程序以高权限打开文件描述符，但未关闭，然后又创建了低权限的进程，那么新进程就能够读写相关文件，但子进程本身不具有打开该文件的权限。</li>
</ul>
</li>
<li>
<p>符号链接</p>
<blockquote>
<p>快捷方式以及Linux软连接</p>
</blockquote>
<ul>
<li>漏洞：恶意方会利用符号链接诱使应用程序执行不良的操作</li>
</ul>
</li>
</ol>
<h3>3.<strong>【理解掌握】应用程序安全</strong></h3>
<ol>
<li>编译和链接
<ul>
<li>DLL注入：通过共享库向程序注入任意代码的过程。优点是便于调试，缺点是潜在的安全风险，恶意用户能向合法程序注入自己的代码。</li>
</ul></li>
<li>缓冲区溢出攻击
<ul>
<li>当缓冲区是局部变量或帧的参数时，用户的输入可能覆盖返回地址，改变程序的执行；</li>
<li>攻击者利用栈缓冲区的脆弱性，在栈中注入恶意代码，覆盖当前调用的返回地址，从而将执行权限传递给攻击者的恶意代码。</li>
</ul></li>
<li>格式化字符串攻击
<ul>
<li>C库函数如果不输入格式化信息，而是直接使用printf(str)，会出现漏洞；</li>
<li>攻击者指定所使用的格式化字符串作为输入，并可以将输入写入内存的任意位置。如果写入的位置正好覆盖了返回地址、函数指针等，则攻击者能够取得控制权，并在程序的上下文中执行任意代码。</li>
</ul></li>
</ol>
<h2>四、恶意软件</h2>
<h3>1. 内部攻击</h3>
<blockquote>
<p>内部攻击(insider attack)是指控制和保护资产的内部人员利用安全漏洞进行的攻击。<em>也就是内部中出了一个内鬼</em></p>
</blockquote>
<ul>
<li>
<p>后门</p>
<p>后门(backdoor) 是程序中隐藏的功能或命令，有时也称为活门，它允许用户执行一些操作，在正常情况下，这些操作是不允许用户执行的。</p>
</li>
<li>
<p>逻辑炸弹</p>
<p>逻辑炸弹(Logic bomb)是一种程序，它根据一定的逻辑条件执行恶意操作。</p>
</li>
</ul>
<h3>2. <strong>【重点】</strong>计算机病毒</h3>
<blockquote>
<p>计算机病毒是一种能<strong>自我复制</strong>的计算机指令或程序代码，它通过修改其他文件与程序来插入代码，且能<strong>进一步自我复制</strong></p>
<p>病毒的另一个特性是其复制需要某种类型的<strong>用户协助</strong>，如打开电子邮件附件或共享USB驱动器；</p>
</blockquote>
<ul>
<li>特征
<ul>
<li>传染性；</li>
<li>隐蔽性：代码短小精悍，隐藏巧妙；</li>
<li>潜伏性：病毒内部有一套触发机制，不满足触发条件时，除了传染外什么都不破坏；</li>
<li>多态性：不断变种，以防查杀；</li>
<li>破坏性：一旦出发，后果极为严重。</li>
</ul></li>
<li>四个阶段
<ul>
<li>潜伏阶段：此阶段，病毒只是存在——病毒很低调并避免被检测到；</li>
<li>繁殖阶段：此阶段，病毒进行自我赋值，感染新系统中的新文件；</li>
<li>触发阶段：此阶段，一些逻辑条件导致病毒从潜伏或繁殖阶段转换为执行病毒预定的操作；</li>
<li>行动阶段：病毒会执行恶意的操作，这些执行是早已设计好的，成为有效载荷。</li>
</ul></li>
</ul>
<h3>3. 恶意软件攻击</h3>
<blockquote>
<p><strong>主要考病毒、蠕虫和木马的区别</strong></p>
</blockquote>
<ul>
<li>
<p>计算机蠕虫</p>
<blockquote>
<p>计算机蠕虫是一种恶意程序，<strong>不需将自己注入其他程序就能传播</strong>自己的副本，并且<strong>不需要与人交互</strong>。</p>
<p>从技术角度而言，计算机蠕虫不是计算机病毒（不会感染其他程序)</p>
</blockquote>
</li>
<li>
<p>木马</p>
<blockquote>
<p>表面上，它会执行一些有用的任务，</p>
<p>同时会隐形地执行具有负面后果的任务<em>（间谍）</em></p>
</blockquote>
</li>
<li>
<p>Rootkits</p>
<blockquote>
<p>修改系统实用程序或操作系统本身来防止检测</p>
</blockquote>
</li>
</ul>
<h3>4. 对策</h3>
<ul>
<li>
<p>签名：一个签名是一个病毒指纹，如果文件中包含签名，则文件被感染 </p>
<blockquote>
<p>类似于病毒抗原，签名数据库用来储存计算机病毒特征</p>
</blockquote>
</li>
<li>
<p>黑/白名单</p>
</li>
<li>
<p>启发式分析：用于识别新的和<strong>“零日”恶意软件</strong></p>
<blockquote>
<p>零日攻击：指利用<strong>未公开或未修复</strong>的安全漏洞进行的攻击，这种攻击往往能够造成巨大的破坏，因为厂商或用户没有足够的时间和手段来防范。名称来源于开发人员发现漏洞时补丁存在的天数：零天</p>
</blockquote>

<h2>5. 网络安全I</h2>
<h3>1. 以太网</h3>
<ul>
<li>基本概念
<ul>
<li>以太网包括通信所使用的物理介质以及链路层的协议标准IEEE 802.3，是现有局域网采用的最通用的技术标准；</li>
<li>不同帧在以太网电缆上同时传输时会产生冲突，需要丢弃并重传冲突帧。</li>
</ul></li>
</ul>
<h3>2.<strong>【理解】</strong> ARP欺骗(链路层，ARP spoofing)</h3>
<ul>
<li>
<p>ARP</p>
<ul>
<li>
<p>地址解析协议，链路层；</p>
</li>
<li>
<p>功能是将给定主机的网络层地址解析为主机的硬件地址。</p>
</li>
<li>ARP协议简单高效，但<strong>缺乏身份认证</strong>，容易受中间人攻击。</li>
</ul>
</li>
<li>
<p><strong>ARP欺骗</strong></p>
<ul>
<li>原理：攻击者可以向某一主机发送伪ARP应答报文，使其发送的信息无法到达预期的主机或到达错误的主机</li>
</ul>
</li>
<li>预防措施
<ul>
<li>检查相同MAC地址是否在局域网中多次出现；</li>
<li>静态ARP表：网络管理员手动指定路由器的ARP缓存来将具体的MAC地址和特定的IP地址进行绑定。</li>
<li>更加复杂和灵活的措施：anti-arpsroof、XArp、Arpwatch，这些程序会仔细检查所有的ARP数据包，并与所存储的ARP表项记录做比较，以检测并防止ARP欺骗。</li>
</ul></li>
</ul>
<h3>3.<strong>【理解】</strong>IP欺骗(IP spoofing)</h3>
<ul>
<li>
<p>IP</p>
<ul>
<li>网络层协议</li>
<li>
<p>功能是尽力将一个数据包从源节点路由到目的节点</p>
</li>
<li>IP包路由：如果数据包的目的地址与发送数据包的主机在同一个局域网内，则使用ARP协议确定目的地址的MAC地址，并发送包；反之，数据包被传送至局域网的网关处，网关根据路由表来确定如何转发数据包；</li>
<li>TTL(time-to-live)：每个数据包在路由过程中的生存周期，用跳数来决定，一般最大跳数为255；</li>
<li>路由器操作：对每个数据包执行丢弃、发送或转发三个操作；</li>
<li>路由协议：</li>
<li>OSPF(Open shortest path first)协议决定如何在自治系统中路由数据包，其策略是数据包应沿最短路径传输。</li>
<li>BGP (Border gateway protocol)决定如何在自治系统之间路由数据包。</li>
</ul>
</li>
<li>
<p><strong>IP地址欺骗(IP spoofing)</strong></p>
<ul>
<li>原理：恶意用户产生的IP数据包中的<strong>源IP地址是伪造</strong>的，以便冒充其他系统或发件人的身份。</li>
<li>如果攻击者用假冒的源IP地址，那么他不会收到服务器的响应。服务器会把数据包返回给具有假冒IP地址的主机。</li>
<li>拒绝服务攻击</li>
</ul>
</li>
<li>
<p>应对措施</p>
<ul>
<li>边缘路由器在配置时，可以阻止源地址在域内，但实际地址是域之外的数据包；</li>
<li>IP追踪技术：追踪数据包返回到实际源地址的路径。根据追踪到的信息，可以向各种自治系统发送请求，要求自治系统阻止来自该路径的数据包，直到确定恶意软件或恶意用户被清除为止。</li>
</ul>
</li>
</ul>
<h3>4. <strong>【理解】网际控制消息协议(网络层，ICMP)</strong></h3>
<ul>
<li>ICMP协议：用于在主机、路由器之间传递<strong>控制消息</strong>。</li>
<li>ICMP消息类型
<ul>
<li>回显请求(echo request)</li>
<li>回显响应(echo response) </li>
<li>超时(time exceeded)</li>
<li>目的地不可达(destination unreachable)。</li>
</ul></li>
</ul>

<h3>6. 传输层协议</h3>
<ol>
<li>端口：16比特的端口号，用来标识应用层不同服务。</li>
<li>UDP：无连接的、不可靠但速度快。</li>
<li>TCP：面向连接的、可靠的。</li>
</ol>
<ul>
<li><strong>【重点】TCP会话劫持</strong>
<ul>
<li>TCP序列号预测：TCP序列预测攻击企图猜测TCP会话时的初始序列号，以建立伪造的TCP会话。</li>
<li>攻击者针对受害客户端发动拒绝服务攻击；</li>
<li>攻击者向服务器发送一个SYN包，将源IP地址伪造成受害客户端的IP地址；</li>
<li>等待服务器向客户端发送响应之后，攻击者通过发送一个ACK数据包来结束TCP握手，该数据包的序列号是预测的下一个序列号；</li>
<li>攻击者以受害客户端名义向服务器发送请求。</li>
<li>盲注入(Blind injection)：注入包含命令的数据包，从而建立将响应返回给攻击者的连接。</li>
<li>ACK风暴(Blind injection)</li>
<li>盲注入后客户端不会向服务器发送同步消息，导致不同步现象</li>
<li>此时，客户端和服务器会向对方发送ACK消息，每一方都想告诉对方需要开始使用正确的序列号。</li>
<li>这种反复的通信被称为ACK风暴。</li>
<li>完全会话劫持 (complete session hijacking)</li>
<li>当攻击者与目标服务器或客户端在同一网段时，攻击者可以完全劫持已有的TCP会话。使用<strong>数据包嗅探</strong>攻击，攻击者可以知道建立会话时数据包的序列号。</li>
<li>完全会话劫持与ARP欺骗结合的中间人攻击：攻击者首先使用ARP欺骗，将会话双方的通讯流暗中改变，这种改变对会话双方来说是透明。其次，攻击者利用完全会话劫持来截获会话双方的所有消息</li>
<li>针对会话劫持的<strong>安全措施</strong></li>
<li>在IP层或者应用层使用认证和加密</li>
<li>网站应避免创建以安全身份验证措施开始，但后来切换到未加密交换的会话，这样会产生的风险。</li>
</ul></li>
</ul>

<ul>

<li>
<p>DNS攻击</p>
<ul>
<li>
<p>网络嫁接与网络钓鱼：</p>
<ul>
<li>
<p>攻击者把网站发送的请求解析成自己恶意服务器的伪装IP地址，导致受害人浏览或下载不需要的内容</p>
</li>
<li>网络嫁接的一个主要用途是将域名解析为一个网站，该网站表面与所请求网站相同，但实际上是恶意网站，这种攻击被称为网络钓鱼</li>
</ul>
</li>
<li>
<p>DNS缓存中毒</p>
<ul>
<li>攻击者欺骗DNS服务器缓存保存虚假的DNS记录</li>
<li>当域名服务器出现以下情况时，缓存可能会中毒</li>

</ul>
</li>
</ul>
</li>

<ul>

<li>无</li>
</ul></li>

<h3>3. <strong>【重点】隧道技术</strong></h3>
<blockquote>
<p>TCP数据包的内容是不加密的，如果有人窃听TCP连接，他会知道该会话中有效载荷的所有内容；</p>
<p>在隧道协议中，客户端和服务器之间的通信<strong>自动加密</strong>。</p>
</blockquote>
<ul>
<li>
<p><strong>【重点】SSH</strong></p>
<ol>
<li>客户端通过一个<strong>TCP会话连接</strong>到服务器；</li>
<li>客户端与服务器<strong>交换管理细节的信息</strong>，如支持的加密方法、各自协议的版本，每一方都要选择另一方支持的一组协议；</li>
<li>客户端和服务器进行<strong>密钥交换</strong>，创建共享的秘密会话密钥，用会话密钥<strong>加密双方的通信</strong>（但不用于身份验证）。
<ul>
<li>公共密钥身份验证，客户端向服务器发送自己的公钥；</li>
<li>服务器检查是否这密钥已存储在其授权的密钥列表之中。如果在，服务器使用客户的公钥加密挑战，并将其发送给客户端；</li>
<li>客户用自己的私钥解密挑战，并向服务器发回响应，证明自己的身份；</li>
</ul></li>
<li>服务器向客户端<strong>发送可接受身份验证列表</strong>，客户端将按顺序尝试。</li>
<li>一旦身份验证已顺利完成，服务器<strong>允许客户端访问</strong>相应的资源，如命令提示符；</li>
</ol>
</li>
<li>
<p>IPSec</p>
<ol>
<li>IPSec定义了一组协议，为IP数据包提供机密性和真实性;</li>
<li>每个协议都能运行在两种模式下，传输模式或隧道模式
<ul>
<li>传输模式：在原数据包的数据之前，会<strong>插入额外的IPSec的头信息</strong>，只对数据包的有效载荷继续加密或身份验证</li>
<li>隧道模式：构造一个新的数据包，将<strong>IPSec头信息和整个原数据包</strong>（包括它的头）一起封装为新数据包的有效载荷；</li>
</ul></li>
</ol>
</li>
<li>
<p>虚拟专用网络VPN（了解）</p>
<blockquote>
<p>尽管使用不受信任的网络进行传输，VPN也能提供数据的保密性、完整性</p>
</blockquote>
<ul>
<li>远程访问VPN：允许授权的用户访问私有网络，一般将这种私有网络称为内网；</li>
<li>站点到站点VPN：旨在为两个或更多远程网络提供安全的桥梁</li>
</ul>
</li>
</ul>
<h3>4. 入侵检测</h3>
<blockquote>
<p>考点：真阳假阳</p>
</blockquote>
<ul>
<li>
<p>入侵检测事件两种类型的错误</p>
<ul>
<li>误报：当事件是良性活动而不是入侵时就发出警报（浪费时间和资源）；</li>
<li>漏报：当事件是入侵的恶意事件，未发出警报（系统受到损害，管理员未察觉）；</li>
</ul>
</li>
<li>
<p><strong>【重点】</strong>基率谬误：根据理解进行简单计算</p>
<blockquote>
<p>假设IDS准确度为99％，假阳性或假阴性的概率为1％</p>
<p>入侵检测系统生成1,000,000+100个日志条目，1,000,000个良性事件，100个恶意事件</p>
<ul>
<li>假阴性的概率为1％：100个恶意事件中，99个将被检测为恶意，有1个假阴性；</li>
<li>假阳性的概率为1％：1,000,000个良性事件中，10,000个将被错误地识别为恶意事件。</li>
</ul>
</blockquote>
</li>
</ul>

<h3>5. <strong>【重点】SQL注入攻击</strong></h3>

</blockquote>
<p><img src="https://cdn.aweip.com/SQL%E6%B3%A8%E5%85%A5.png" alt="SQL注入" /></p>
<ol>
<li>
<p>SQL注入条件</p>
<ul>
<li>web应用程序从表单中获取用户输入；</li>
<li>用户输入的信息直接用于构造提交到数据库的SQL查询；</li>

</li>
<li>SQL 注入的防范

</ul></li>
<li>使用安全函数：比如 OWASP ESAPI； </li>
<li>摒弃动态SQL语句，改用存储过程来访问和操作数据；</li>
<li>最小权限原则：避免 Web 应用直接使用 root，dbowner 等高权限账户直接连接数据库。</li>
</ul></li>
</ol>
<h2>8.密码学概述</h2>
<h3>1. 加密基本概念</h3>
<ul>
<li>场景 (Scenario)
<ul>
<li>Alice希望发送一条消息（明文P）给Bob。</li>
<li>通信信道是不安全的，有可能被窃听。</li>
<li>如果Alice和Bob之前已经协商好了一个对称加密方案和一个密钥K，那么该消息就可以加密后再进行传输（密文C）。</li>
</ul></li>
<li>符号 (Notation)
<ul>
<li>密钥<katex-inline>K</katex-inline></li>
<li>加密算法<katex-inline>E_K(P)</katex-inline></li>
<li>解密算法<katex-inline>D_K(C)</katex-inline></li>
<li>密文长度通常和明文长度相同</li>
<li>加密/解密是所有n位二进制序列(n-bit arrays)构成的集合上的(双射)置换函数</li>
</ul></li>
<li>效率 (Efficiency)
<ul>
<li>加密算法<katex-inline>E_K(P)</katex-inline>和解密算法<katex-inline>D_K(C)</katex-inline>必须是高效的</li>
</ul></li>
<li>一致性 (Consistency)
<ul>
<li>对密文解密后可恢复出明文: <katex-inline>D_K(E_K(P))=P</katex-inline></li>
</ul></li>
</ul>
<h3>2. <strong>【理解区分】</strong>攻击者的主要类型</h3>
<ol>
<li>
<p>唯密文攻击(ciphertext-only attack)</p>
<blockquote>
<p>攻击者收集一个或多个消息的<strong>密文</strong>；</p>
</blockquote>
</li>
<li>
<p>已知明文攻击(known-plaintext attack)</p>
<blockquote>
<p>攻击者收集一个或多个 <strong>明文—密文对</strong>；</p>
</blockquote>
</li>
<li>
<p>选择明文攻击(chosen-plaintext attack)</p>
<blockquote>
<p>攻击者可收集<strong>指定的明文</strong>对应的<strong>密文</strong>信息;</p>
</blockquote>
</li>
<li>
<p>选择密文攻击(chosen-ciphertext attack)</p>
<blockquote>
<p>攻击者可收集<strong>指定的密文</strong>对应的<strong>明文</strong>信息。</p>
</blockquote>
</li>
</ol>
<h3>3. 替换密码和频率分析</h3>
<blockquote>
<p>n位二进制位的英语文本信息熵<katex-inline>2^{1.25*n/8}≈2^{0.16n}</katex-inline></p>
</blockquote>
<h3>4. 一次一密</h3>
<blockquote>
<p>每次都是完全随机地选择移动量，在密文中字母表的每个字母出现的概率几乎相同</p>
</blockquote>
<p>弱点：密钥块的长度m必须和明文的长度n相同</p>
<h3>5. 分组密码</h3>
<blockquote>
<p>明文和密文具有固定的长度b（例如，128位）；</p>
<p>长度为 n 的明文被划分为 m 个序列块 <katex-inline>P[0], …, P[m-1]（n ≤ bm＜ n + b</katex-inline>）；</p>
<p>每条消息被划分成一系列的块，基于这些数据块来进行加密或解密。</p>
</blockquote>
<ul>
<li>高级加密标准（AES）：AES加密算法的128位版本进行十轮的处理
<ul>
<li>每一轮都对128位的数组（<katex-inline>state</katex-inline>）执行可逆替换;</li>
<li>初始<katex-inline>stateX_0</katex-inline>是明文P与密钥K的异或： <katex-inline>X_0 = P XOR K</katex-inline>;</li>
<li>第 <katex-inline>i</katex-inline> 轮 (<katex-inline>i = 1, …, 10</katex-inline> ) 接受 <katex-inline>state X_{i-1}</katex-inline> 作为输入，并产生 <katex-inline>state X_{i-1}</katex-inline>;</li>
<li>最后一轮输入密文<katex-inline>C</katex-inline>：<katex-inline>C = X_{10}</katex-inline>;</li>
</ul></li>
</ul>
<img src="https://cdn.aweip.com/image-20230302201300202.png" alt="image-20230302201300202" style="zoom: 33%;" />
<h3>6. 【区分】分组密码优缺点</h3>
<ul>
<li>电子密码本（ECB）模式 （最简单的一种模式）
<ul>
<li>优点：ECB模式适合于数据较少的情况，比如密钥和初始向量的加密；</li>
<li>缺点：对于文件和图片这类很长的消息，ECB模式可能是不安全的，因为ECB模式会揭示在分组流中出现的模式，即相同的分组会使用相同的加密方式。</li>
</ul></li>
<li>密码分组链接（CBC）模式
<ul>
<li>优点：</li>
<li>没有在明文中泄露明文的模式；</li>
<li>是最常用的模式之一；</li>
<li>快速且相对简单。</li>
<li>缺点</li>
<li>需要所有数据块进行有序的可靠传输；</li>
<li>CBC模式不适用于允许丢包的应用程序，如音频流和视频流。</li>
</ul></li>
</ul>
<h3>7. 流密码</h3>
<ul>
<li>密钥流 
<ul>
<li>伪随机序列 <katex-inline>S = S[0], S[1], S[2], ……</katex-inline></li>
<li>可以每次生成1位或者1个字节</li>
</ul></li>
<li>流密码 
<ul>
<li>密钥流和明文流进行对位异或操作 <katex-inline>C[i] = S[i]⊕P[i]</katex-inline>;</li>
<li>适用于快速写入的任意长度的明文，例如流媒体数据.</li>
</ul></li>
<li>同步流密码 
<ul>
<li>密钥流的生成只依靠密钥K </li>
<li>如果明文是带有序列号的包，那么同步流密码可在不可靠信道下工作</li>
</ul></li>
<li>自同步流密码 
<ul>
<li>使用密钥K和前q个密文来生生成密钥流 </li>
<li>在接收到q个密文后会自动与密钥流生成器同步，如果数字被丢弃或添加到明文流中，更容易恢复</li>
</ul></li>
</ul>

<h4>4. 哈希函数</h4>
<blockquote>
<p>h将可变长度的消息P作为输入，产生固定长度的Hash值<katex-inline>x = h(P)</katex-inline>，称函数值h(P)为P的哈希值或消息摘要。</p>
</blockquote>
<ul>
<li>碰撞(collision)：指的是存在两个消息P和Q被映射到相同的哈希值，即 <katex-inline>h(P) = h(Q)</katex-inline></li>
<li>碰撞是不可避免的</li>
<li>哈希值的计算时间应该和输入消息的长度成正比</li>
</ul>
<h5>生日攻击</h5>
<ul>
<li>攻击者可以通过生日攻击的蛮力技术来对密码学Hash函数进行攻击，主要危害其抗碰撞性，主要步骤如下：  
<ul>
<li>随机产生消息序列<katex-inline>X_1, X_2, X_3,</katex-inline>…  </li>
<li>对于每个<katex-inline>X_i</katex-inline>计算Hash值<katex-inline>y_i = h(X_i)</katex-inline>并且检测<katex-inline>y_i</katex-inline>是否等于<katex-inline>y_j  ( j &lt; i )</katex-inline></li>
<li>直至找到碰撞即停止</li>
</ul></li>
</ul>
<p><strong>1/2长度：通常根据输出大小的一半来考虑加密散列函数安全，比如256位抗冲突Hash函数的安全是128位</strong></p>

<h2>9. 安全模型与实践</h2>
<h3>1. 策略、模型与信任基本概念</h3>
<ol>
<li>
<p>安全策略（5部分）</p>
<ul>
<li>
<p>主体（Subject）：与系统交互的代理，可以根据特定的个人定义，也可以根据个人群体在组织中可能持有的角色或级别来定义。</p>
<blockquote>
<p>个人可以通过姓名或职称来识别，可以用术语来定义组。此类别还包括外部人员，如攻击者和来宾。</p>
</blockquote>
</li>
<li>
<p>客体（Object）：客体是安全策略要保护和管理的信息与计算资源。</p>
<blockquote>
<p>信息包括重要文档、文件与数据库，计算资源包括服务器、工作站和软件。</p>
</blockquote>
</li>
<li>
<p>行动（Action）：主体对客体可能（或不可能）执行的操作。</p>
<blockquote>
<p>操作一般包括文档的读取和写入、在web服务器上更新软件以及访问数据库的内容。</p>
</blockquote>
</li>
<li>
<p>权限（Permission）：主体、操作与客体之间的映射，权限明确规定允许或禁止哪些操作。 </p>
</li>
<li>保护（Protection）：策略中包含的特定安全特性或规则，以帮助实现特定的安全目标，如保密性、完整性、可用性或匿名性</li>
</ul>
</li>
<li>安全模型：是一种抽象的、为管理员指定安全策略提供概念语言。</li>
</ol>
<h3>2. 访问控制模型</h3>
<ul>
<li>
<p>Bell-La Padula模型：信息只能从低安全级别流向高安全级别</p>
<ul>
<li>军事分级层次结构；</li>
<li>系统有四种安全级别：最底层的是不保密（unclassified）、然后安全性呈升序的分别是秘密（confidential）、机密（secret）、绝密（top - secret）；</li>
<li>每个文件归类于一个安全级别；</li>
<li>每个用户都会在一个安全级别得到放行许可（clearance）。</li>
</ul>
</li>
<li>
<p>Biba模型：信息只能从较高的完整性级别下降到较低的完整性级别</p>
<ul>
<li>Biba模型的完整性级别表明对象和用户的可信度或准确度，而不是确定保密级别；</li>
<li>不允许从下一级阅读，也不允许写到上层。</li>
</ul>
</li>
<li>低水印模型：对Biba模型的扩展，它放宽了“不可向下读”的限制</li>
<li>克拉克-威尔逊模型：不处理文档机密性或完整性，而是处理执行事务的系统</li>
<li>中国墙模型：每个用户只能从每个利益冲突类访问一个资源</li>
</ul>
<h3>3. 渗透测试</h3>
<blockquote>
<p>从攻击者(黑客)的角度测试系统和体系结构的安全性，在固定时间内必须获得的具有预定目标的“模拟攻击”</p>
</blockquote>
<h3>4. <strong>【重点】Kerberos</strong></h3>
<blockquote>
<p>基于可信第三方（Trusted Third Party，TTP）的认证协议；</p>
<p>MIT的雅典娜项目组（Athena Group）开发的认证服务系统。</p>
</blockquote>
<ul>
<li>Kerberos使用票据（ticket）的概念作为证明用户身份的令牌。票据是存储会话密钥的数字文件。在登录会话中，通常会发送会话密钥，然后代替在kerberized服务中的密码；</li>
<li>
<p>在身份验证过程中，客户端会收到两个票据</p>
<ul>
<li>票据授予票据（ticket-granting ticket，TGT）：用户和会话密钥的全局标识符；</li>
<li>服务票据（service ticket）：对用户进行身份验证，确定用户能否使用特殊服务。</li>
</ul>
</li>
<li>
<p>票据都有时间戳，用于表明票据的有效期限；</p>
</li>
<li>
<p>为了实现安全的身份验证，Kerberos使用可信第三方作为密钥分发中心（key distribution center，KDC）,由两个部分组成：</p>
<ul>
<li>身份验证服务器（authentication server，AS）：用于执行用户身份验证。</li>
<li>票据授予服务器（ticket granting server，TGS）：用于向用户授予票据。</li>
</ul>
</li>
<li>
<p>身份验证服务器维护存储用户和服务密钥的数据库。对用户提供的密码执行单向散列来生成用户的密钥。</p>
</li>
<li>
<p>身份验证大致流程：</p>
<ol>
<li>客户端与身份验证服务器（AS）互相进行身份验证；</li>
<li>客户端与票据授予服务（TGS）互相进行身份验证；</li>
<li>客户端与服务（S）互相进行身份验证，此要为客户端提供服务。</li>
</ol>
</li>
<li>
<p>身份验证：</p>
<ol>
<li>
<p>1.用户在客户端计算机上输入用户名和密码，执行哈希（hash）函数对输入进行散列操作，形成客户端的密钥。</p>
</li>
<li>
<p>客户端与AS联系，AS作如下反应：</p>
<ul>
<li>使用客户端密钥KC（存储在AS数据库中）加密客户端-TGS的会话密钥KGT。</li>
<li>使用TGS密钥KT（存储于AS数据库中）加密票据授予票据（TGT）。TGT包括密钥KCT和有效期。</li>
</ul>
</li>
<li>
<p>客户端使用KC解密TGS会话密钥KCT。为了请求服务，客户端向TGS发送如下两个消息：</p>
<ul>
<li>TGT（仍然使用TGS的密钥KT加密）和所请求服务名称S。</li>
<li>验证令牌（authentication token）由客户ID和时间戳组成，使用客户端TGS会话密钥KCT进行加密。</li>
</ul>
</li>
<li>
<p>TGS使KT解密TGS，从而得到客户端TGS的会话密钥KCT和TGT的有效期。在有效期之内，TGS使用密钥KCT解密身份验证令牌，向客户端发送如下两个消息：</p>
<ul>
<li>
<p>使用KCT加密的新的客户端-服务器会话密钥（client-server session key） KCS。</p>
</li>
<li>使用具体服务的密钥KS加密客户端-服务器票据（client-server ticket），其中TGS已知密钥KS 。票据包含客户端ID、网络地址、有效期、密钥KCS。</li>
</ul>
</li>
<li>
<p>在对客户端-服务器会话密钥KCS解密后，为了使服务对客户端进行身份验证，客户端发送以下两个消息：</p>
<ul>
<li>在上个步骤中，TGS发送的客户端-服务器的票据。</li>
<li>使用KCS加密的客户端ID和时间戳。</li>
</ul>
</li>
<li>
<p>服务使用自己的密钥KS解密客户端-服务器的票据，得到客户端-服务器的会话密钥KCS 。使用KCS解密客户端ID和时间戳。最后，为了向客户端证码自己的身份，它使用时间戳加1，并用KCS重新加密送回客户端。</p>
</li>
<li>客户端使用KCS解密并验证这个响应，如果验证成功，就可以开始客户端-服务器的会话了。</li>
</ol>
<blockquote>
<p><strong>Remark：</strong>在票据授予票据的有效期内，客户端为了访问多个服务，可以一直重复协议中的步骤3~7。</p>
</blockquote>
</li>
</ul>

<h2>10. 分布式应用程序的安全</h2>
<h3>1. 数据库安全</h3>
<ul>
<li>
<p>为了解决一致性和可靠性问题，大多数数据库在执行更新时使用<strong>两阶段提交协议 (two-phase commit)</strong>。</p>
</li>
<li>最小特权原则 (Least-privilege principle)：实现适当的访问控制应遵循最小特权原则，使每个用户都拥有完成自己任务所必需的权限，但除此之外，不再拥有其他的权限。</li>
<li>
<p>特权分离原则 (Separation of privilege principle)：实现适当的访问控制还应遵循特权分离原则，以便不同的用户具有不同的权限，这取决于他们需要执行的不同任务。</p>
</li>
<li>
<p>推理攻击</p>
<blockquote>
<p>即使删除或屏蔽掉身份信息，攻击者仍能将其他的信息与数据库结合，得到底层的数据。</p>
</blockquote>
</li>
</ul>
