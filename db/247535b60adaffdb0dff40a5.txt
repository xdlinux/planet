<h2 id="ic卡前置知识">IC卡前置知识</h2>
<p>别被术语绕晕：卡片技术分级
​市面上的卡片和称呼五花八门（ID、IC、RFID……），为了看清本质，我们可以按安全等级或者发展历史将它们分为三类：
​</p>
<ul>
<li>
<p>只读存储卡 (RO Memory Card)</p>
<ul>
<li>​代表：磁条卡 (Magnetic Stripe Card) / 只读存储卡 (RO Memory Card)。</li>
</ul>
<p>- ​原理：静态明文存储，类似录音带，数据明文记录。</p>
<ul>
<li>​安全性：易被 <strong>侧信道攻击</strong> 或 <strong>重放攻击</strong> 。</li>
</ul>
</li>
<li>
<p>非接触式逻辑加密卡 (Contactless Memory Card)</p>
<ul>
<li>
<p>代表：Mifare Classic (M1)、HID iCLASS Legacy。</p>
</li>
<li>
<p>​特征：遵循 <strong>ISO 14443 Type A</strong> 协议（部分）。</p>
</li>
<li>
<p>​原理：卡内有存储区和简单的逻辑电路。使用专有的 <strong>Crypto-1</strong> 流加密算法。它的本质依然是“存储器”，只是在读写前加了一道“口令验证”。</p>
</li>
<li>
<p>​安全性：验证漏洞，noise分析逆向，硬嵌套攻击。</p>
</li>
</ul>
</li>
<li>
<p>双界面CPU卡 (Dual Interface CPU Card)</p>
<ul>
<li>
<p>​代表：身份证、银行 IC 卡、Mifare DESFire。</p>
</li>
<li>
<p>​特征：内置微型单片机（MCU）甚至操作系统（COS）。</p>
</li>
<li>
<p>原理：挑战-响应机制，不是“被读取”，而是“在对话”。读卡器发随机数（Challenge），卡片用私钥计算后回传结果（Response），私钥永不出卡。</p>
</li>
<li>
<p>安全性：极高，目前基本无法通过“复制”破解。方向需要转向芯片漏洞或者攻击服务器来拿到密钥而不是卡本身。</p>
</li>
</ul>
</li>
</ul>
<h3 id="深入-mifare-classic-1k-s50">深入 Mifare Classic 1K (S50)</h3>
<p>既然NCC决定动手Hack，那就必须了解我们手中的“靶子”到底长什么样。Mifare Classic 1K（简称M1卡）不仅是酒店房卡，也是很多门禁卡、饭卡的前身。</p>
<h4 id="1-地图全貌存储结构-memory-structure">1. 地图全貌：存储结构 (Memory Structure)</h4>
<p>这就好比一个有16个抽屉的柜子，每个抽屉里有4个小盒子。</p>
<ul>
<li>
<p><strong>总容量</strong>：1024 字节 (1KB)。</p>
</li>
<li>
<p><strong>分区 (Sectors)</strong>：共有 <strong>16个扇区</strong> (Sector 0 - Sector 15)。</p>
</li>
<li>
<p><strong>区块 (Blocks)</strong>：每个扇区有 <strong>4个区块</strong> (Block 0 - Block 3)，每个区块 <strong>16字节</strong>。</p>
</li>
</ul>
<p><strong>特别注意这两个特殊区域：</strong></p>
<ul>
<li>
<p><strong>Sector 0, Block 0 (厂商块/Manufacturer Block)</strong>：</p>
<ul>
<li>
<p>这是卡片的“身份证”。包含唯一标识符和厂商数据。</p>
</li>
<li>
<p><strong>出厂固化</strong>：在正规卡上，这里是<strong>只读</strong>的。</p>
</li>
<li>
<p><strong>黑客特供</strong>：市面上的“UID卡”或“CUID卡”可以通过特殊指令修改这里，从而完美克隆一张卡片的ID。</p>
</li>
</ul>
</li>
<li>
<p><strong>每个扇区的 Block 3 (尾块/Sector Trailer)</strong>：</p>
<ul>
<li>
<p>这是每个扇区的“控制室”。绝对不能乱写，否则扇区会锁死变砖。</p>
</li>
<li>
<p>结构如下： <code>[ Key A (6字节) ] [ 存取控制位 (4字节) ] [ Key B (6字节) ]</code></p>
</li>
</ul>
</li>
</ul>
<h4 id="2-加密与验证crypto-1-协议">2. 加密与验证：Crypto-1 协议</h4>
<p>M1卡不像U盘插上就能读，它和读卡器之间有一个“对暗号”的过程。</p>
<ul>
<li>
<p><strong>算法</strong>：<strong>Crypto-1</strong>。这是一个私有的流加密算法。</p>
</li>
<li>
<p><strong>流程</strong>：</p>
<ol>
<li>
<p>读卡器呼叫卡片。</p>
</li>
<li>
<p>卡片发送随机数（Challenge）。</p>
</li>
<li>
<p>读卡器用密钥（Key A或Key B）加密这个随机数并寄回。</p>
</li>
<li>
<p>卡片验证，如果正确，双方建立加密通道。</p>
</li>
</ol>
</li>
<li>
<p><strong>漏洞</strong>：NCC使用的 Flipper Zero 之所以能秒解，是因为Crypto-1算法的随机数生成器（PRNG）极其脆弱。通过 **Nested Attack ** 或 <strong>Darkside Attack</strong>，可以在不知道密码的情况下，利用漏洞反推密钥。</p>
</li>
</ul>
<h4 id="3-核心机制存取控制位-access-bits">3. 核心机制：存取控制位 (Access Bits)</h4>
<p>在每个扇区的 Block 3 中，中间那 4 个字节决定了谁有资格读写数据。</p>
<ul>
<li>
<p><strong>默认值</strong>：<code>FF 07 80 69</code></p>
<ul>
<li>这意味着：Key A 是万能钥匙（可读写所有数据，可修改Key B），Key B 也是万能的。</li>
</ul>
</li>
<li>
<p><strong>危险操作</strong>：控制位有冗余校验机制（正反存）。如果你算错了控制位并写入，这个扇区就会<strong>永久锁死</strong>，再也无法认证（这就是传说中的“写死卡”）。</p>
</li>
</ul>
<h4 id="4-校验位规则详解-the-checksum-rules">4. 校验位规则详解 (The Checksum Rules)</h4>
<p>这是NCC最关心的部分。卡片里其实藏着两层校验：</p>
<p><strong>(1) 物理层校验：BCC (Block Check Character)</strong> 这位于 <strong>Sector 0, Block 0</strong> 的第 5 个字节。它的作用是验证 UID 是否传输出错。</p>
<ul>
<li>
<p><strong>规则</strong>：<strong>异或校验 (XOR Checksum)</strong>。</p>
</li>
<li>
<p><strong>公式</strong>：<code>UID0 ^ UID1 ^ UID2 ^ UID3 = BCC</code></p>
</li>
<li>
<p><strong>例子</strong>：如果 UID 是 <code>11 22 33 44</code>，那么 BCC = <code>11 ^ 22 ^ 33 ^ 44</code>。如果不符合这个规则，读卡器连理都不理这张卡。</p>
</li>
</ul>
<p>既然有13个扇区，那有很多空间放东西，可以弱水三千只取一瓢饮，只用一个扇区，也可以全部扇区都用上。为了工程上的方便，往往只用一个扇区，重要信息再加密一下。</p>
