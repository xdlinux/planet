<h1><a id="content-derp-介绍" href="https://blog.lsy223622.com/archives/69/#content-derp-%E4%BB%8B%E7%BB%8D" class="heading-permalink" aria-hidden="true" title="Permalink"></a>DERP 介绍</h1>
<blockquote>
<p>DERP (Designated Encrypted Relay for Packets) servers manage device connections and NAT traversal. They serve two primary purposes: negotiating direct connections between tailnet devices and serving as a relay server when a direct connection isn’t possible.
Most connections between tailnet devices only use DERP servers to establish a direct connection to another tailnet device. But as a last resort, when a direct connection isn’t possible due to hard NAT, firewalls, or another reason, devices can communicate using a DERP server as a relay. DERP servers are dual-stack, meaning they support IPv4 and IPv6. As a result, they can facilitate connections between IPv4-only and IPv6-only devices.
Data sent between devices using a DERP relayed connection is encrypted using WireGuard. Because Tailscale private keys never leave the device where they were generated, it’s impossible for a DERP server to decrypt your traffic. A DERP server blindly forwards already-encrypted traffic from one device to another.</p>
<p><a rel="noopener noreferrer" href="https://tailscale.com/kb/1232/derp-servers">derp-servers</a></p>
</blockquote>
<blockquote>
<p>Some especially cruel networks block UDP entirely, or are otherwise so strict that they simply cannot be traversed using STUN and ICE. For those situations, Tailscale provides a network of so-called DERP (Designated Encrypted Relay for Packets) servers. These fill the same role as TURN servers in the ICE standard, except they use HTTPS streams and WireGuard keys instead of the obsolete TURN recommendations.</p>
<p><a rel="noopener noreferrer" href="https://tailscale.com/blog/how-tailscale-works#encrypted-tcp-relays-derp">encrypted-tcp-relays-derp</a></p>
</blockquote>
<p>简而言之呢就是为 Tailscale 设计的 TCP 中继服务。</p>

<h1><a id="content-部署" href="https://blog.lsy223622.com/archives/69/#content-%E9%83%A8%E7%BD%B2" class="heading-permalink" aria-hidden="true" title="Permalink"></a>部署</h1>
<h2><a id="content-tailscale" href="https://blog.lsy223622.com/archives/69/#content-tailscale" class="heading-permalink" aria-hidden="true" title="Permalink"></a>Tailscale</h2>
<p>使用以下命令安装 Tailscale：</p>
<pre><code class="language-shell">curl -fsSL https://tailscale.com/install.sh | sh
</code></pre>
<p>然后使用 <code>tailscale up</code> 命令启动并登录账号。</p>
<h2><a id="content-docker" href="https://blog.lsy223622.com/archives/69/#content-docker" class="heading-permalink" aria-hidden="true" title="Permalink"></a>Docker</h2>
<p>创建上述内容的 <code>docker-compose.yml</code>，把 <code>example.com</code> 替换成你的域名，然后使用 <code>docker compose up -d</code> 启动服务。</p>
<pre><code class="language-dockerfile">services:
  derp:
    image: fredliang/derper:latest
    container_name: derp
    restart: always
    ports:
      - &#34;8443:8443&#34;
      - &#34;3478:3478/udp&#34;
    environment:
      DERP_DOMAIN: example.com
      DERP_ADDR: :8443
      DERP_VERIFY_CLIENTS: true
      DERP_CERT_MODE: letsencrypt
      DERP_CERT_DIR: /app/certs
      DERP_STUN: true
    volumes:
      - /usr/share/zoneinfo/Asia/Shanghai:/etc/localtime:ro
      - /var/run/tailscale/tailscaled.sock:/var/run/tailscale/tailscaled.sock
</code></pre>
<h2><a id="content-nginx" href="https://blog.lsy223622.com/archives/69/#content-nginx" class="heading-permalink" aria-hidden="true" title="Permalink"></a>Nginx</h2>
<p>使用 Nginx 反向代理 derp 的 http 端口，域名和证书自己准备。</p>
<pre><code class="language-nginx">server {
    listen 443 ssl http2;
    server_name example.com;

    ssl_certificate /etc/letsencrypt/live/example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/example.com/privkey.pem;

    location / {
        proxy_redirect off;
        proxy_pass http://127.0.0.1:8443;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection &#34;upgrade&#34;;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
</code></pre>
<h2><a id="content-访问控制" href="https://blog.lsy223622.com/archives/69/#content-%E8%AE%BF%E9%97%AE%E6%8E%A7%E5%88%B6" class="heading-permalink" aria-hidden="true" title="Permalink"></a>访问控制</h2>
<p>访问 Tailscale 管理面板的 <a rel="noopener noreferrer" href="https://login.tailscale.com/admin/acls">Access Control 页面</a>，编辑以下内容：</p>
<pre><code class="language-yaml">{
  &#34;derpMap&#34;: {
    &#34;OmitDefaultRegions&#34;: true,
    &#34;Regions&#34;: {
      &#34;114&#34;: {
        &#34;RegionID&#34;:   114,
        &#34;RegionCode&#34;: &#34;exp&#34;,
        &#34;RegionName&#34;: &#34;Example&#34;,
        &#34;Nodes&#34;: [
          {
            &#34;Name&#34;:     &#34;example&#34;,
            &#34;RegionID&#34;: 114,
            &#34;HostName&#34;: &#34;example.com&#34;,
            &#34;DERPPort&#34;: 443,
          },
        ],
      },
    },
  },
  &#34;acls&#34;: [
    ......
  ],
  ... 其他原有内容 ...
}
</code></pre>
<ul>
<li>
<code>&#34;OmitDefaultRegions&#34;: true</code> 意为不使用官方提供的公共 DERP 服务器，因为都在境外，一般延迟较高，但也可以选择选择 <code>false</code> 来保留备用。</li>
<li>编号、名称自己随便取，域名和端口和上面的 Nginx 配置一致。如果保留了公共 derp 服务器，注意自己服务器的各项信息不要和原有的冲突。</li>
</ul>
<h1><a id="content-使用" href="https://blog.lsy223622.com/archives/69/#content-%E4%BD%BF%E7%94%A8" class="heading-permalink" aria-hidden="true" title="Permalink"></a>使用</h1>
<p>在客户端安装并登录 Tailscale，在客户端的命令行输入 <code>tailscale netcheck</code>，如果能看到 DERP 服务器的信息，说明部署成功。</p>
