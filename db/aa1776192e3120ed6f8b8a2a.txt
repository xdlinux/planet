<h1>第一章 计算机网络体系结构</h1>
<h2>I.计算机网络概述</h2>
<h3>概念</h3>
<ul>
<li>计算机网络是互连的、自治的计算机集合。</li>
<li>由节点（Node）和连接这些节点的链路（Link）组成。</li>
</ul>
<h3>组成</h3>
<ul>
<li>组成部分：硬件、软件、协议</li>
<li>工作方式：
<ul>
<li>边缘部分：用户直接使用的主机</li>
<li>核心部分：网络的基础设施，如路由器、交换机等</li>
</ul></li>
<li>功能组成：
<ul>
<li>通信子网：负责数据传输</li>
<li>资源子网：负责资源管理</li>
</ul></li>
</ul>
<h3>功能</h3>
<ul>
<li>数据通信</li>
<li>资源共享</li>
<li>分布式处理</li>
<li>提高可靠性</li>
<li>负载均衡</li>
</ul>

<h4>种类</h4>

<h4>区别</h4>
<ul>
<li>
<p>计算机的数据传送往往是<strong>突发式</strong>的，采用电路交换时通信线路的利用率很低。报文交换和分组交换不需要建立连接（即预先分配通信资源），在传送计算机的突发数据时可以提高通信线路的利用率</p>
</li>
<li>将报文构造成若干个更小的分组进行分组交换，比将整个报文进行报文交换的时延要小，并且还可以避免太长的报文长时间占用链路，有利于差错控制，同时具有更好的灵活性。</li>
</ul>

<blockquote>
<p>[!Important]</p>
<p>速率中的K、M、G表示的是十进制，分别为<katex-inline>10^3</katex-inline>、<katex-inline>10^6</katex-inline>、<katex-inline>10^9</katex-inline></p>

<ol>
<li>
<p>速率</p>
</li>
<li>
<p>带宽</p>
<ul>

<li>计算机网络：最高数据传输速率</li>

<li>发送时延 <katex-inline>t_s = 数据块长度/发送速率</katex-inline></li>
<li>传播时延 <katex-inline>t_c = 信道长度/传播速率</katex-inline></li>

<li>排队时延</li>
</ul>

</li>
<li>
<p>时延带宽积: 传播时延 * 带宽</p>
</li>

</li>
<li>
<p>！信道利用率 <katex-inline>U</katex-inline></p>
<ul>
<li>空闲时延 <katex-inline>D_0</katex-inline>、当前时延 <katex-inline>D</katex-inline></li>
<li><katex-inline>D = \frac{D_0}{1-U}</katex-inline>，<katex-inline>U</katex-inline> 越大，当前时延 <katex-inline>D</katex-inline> 越大</li>
</ul>
</li>
</ol>
<h2>II.计算机网络体系结构</h2>
<h3>分层结构</h3>
<h4>分层基本原则</h4>
<ul>
<li>每层实现特定功能</li>
<li>各层间由可以互相通信的接口</li>
<li>下层独立于上层，即没有上层也能工作</li>
<li>上层==单向==使用下层服务</li>
</ul>
<h4>结构元素</h4>
<ol>
<li>实体</li>
</ol>
<ul>
<li>实体：在通信过程中能够发送或接收信息的硬件或软件模块</li>
<li>对等实体：在通信过程中能够相互通信的实体</li>
</ul>
<ol start="2">
<li>
<p>协议数据单元（PDU）：对等层水平传递的数据单元，分为数据和控制信息</p>
</li>
<li>
<p>服务数据单元（SDU）：对等层垂直传递的数据单元，服务上层</p>
</li>
<li>协议控制信息（PCI）：对等层水平传递的控制信息</li>
</ol>
<blockquote>
<p>[!Note]
第n层收到的PDUs称为n-1层的SDUs，加上第n层的PCI就构成了n层的PDUs</p>
</blockquote>

<h3>！OSI与TCP/IP对比</h3>
<ol>
<li>OSI 是理论模型，TCP/IP 是实际模型</li>
<li>OSI 七层，TCP/IP 四层</li>
<li>OSI 在网络层支持面向连接和无连接服务，而 TCP/IP 只支持无连接服务</li>
<li>OSI 的传输层只提供端到端可靠传输，而 TCP/IP 的传输层提供不可靠传输 UPD 和可靠传输 TCP</li>
</ol>

<h2>I.通信原理</h2>
<h3>基本名词</h3>
<ul>
<li>
<p>数据、信号和码元</p>
<ul>
<li>数据：传送信息的实体</li>
<li>信号：数据的电气和电磁表现</li>
<li>码元：不同离散数字的基本波形</li>
</ul>
<blockquote>
<p>模拟数据（信号）是连续的</p>
<p>数字数据（信号）是离散的</p>
</blockquote>
</li>
<li>
<p>信源、信道和信宿</p>
<ul>
<li>信源：产生和发送数据的源头</li>
<li>信宿：接收数据的终点</li>
<li>信道：</li>
<li><strong>基带</strong>信号是数字0/1；<strong>宽带</strong>信号是模拟波形</li>
<li>数字信道传输数字信号；模拟信道传输模拟信号</li>
</ul>
</li>
<li>
<p>速率、波特和带宽</p>
<ul>
<li>码元传输速率（波特率Baud/s）</li>
<li>信息传输速率（比特率b/s）</li>
<li>带宽</li>
<li>模拟信号通信：频率范围Hz</li>
<li>计算机网络：最高数据传输速率b/s</li>
</ul>
</li>
</ul>
<h3>传输方式</h3>
<ul>
<li>
<p>串行并行</p>
<ul>
<li>局域网：串行</li>
<li>计算机内部：并行</li>
</ul>
</li>
<li>同步异步
<ul>
<li>同步传输</li>
<li>外同步：外加时钟</li>
<li>内同步：信号编码同步</li>
<li>==异步传输==：字节间异步，字节内同步</li>
</ul></li>
<li>单工双工
<ul>
<li>单向：广播</li>
<li>半双工：对讲机</li>
<li>全双工：互联网</li>
</ul></li>
</ul>
<h3>编码与调制</h3>
<h4>数字数据-&gt;数字信号</h4>
<ol>
<li>归零（RZ）编码
<ul>
<li>0：前低后零</li>
<li>1：前高后零</li>
</ul></li>
<li>不归零（NRZ）编码（==无自同步==）
<ul>
<li>0：低电平</li>
<li>1：高电平</li>
</ul></li>
<li>曼彻斯特编码：<strong>以太网</strong>
<ul>
<li>设定初始信号形式</li>
<li>码元必定在中间跳变</li>
<li>码元==中间==电平变化表示信号0/1</li>
</ul></li>
<li>差分曼彻斯特编码
<ul>
<li>码元==开始==无跳变表示1，有跳变表示0</li>
</ul></li>
</ol>
<h4>模拟数据-&gt;数字信号</h4>
<blockquote>
<p>奈奎斯特定理：<katex-inline>f_{采样}≥2*f</katex-inline>，才能完整保留信号信息</p>
</blockquote>
<h4>数字数据-&gt;模拟信号</h4>
<ol>
<li>调幅（AM）：载波振幅变化表示0、1</li>
<li>调频（FM）：载波频率变化表示0、1</li>
<li>调相（PM）：载波相位变化表示0、1</li>
<li>正交幅度调制（QAM）：<katex-inline>R = B*log_{2}（mn）</katex-inline></li>
</ol>
<h3>信道容量</h3>
<h4>奈奎斯特定理（无干扰）</h4>
<katex>
奈奎斯特速率v = 2Wlog_{2}V</katex>
<blockquote>
<p><katex-inline>W</katex-inline>：信道频率带宽<strong>范围</strong>（Hz）</p>
<p><katex-inline>V</katex-inline>：码元离散电平数量</p>
</blockquote>
<h4>香农定理（有噪声）</h4>
<katex>
香农速率C = Wlog_{2}(1+\frac{S}{N})</katex>
<blockquote>
<p><katex-inline>W</katex-inline>：信道频率带宽<strong>范围</strong>（Hz）</p>
<p><katex-inline>\frac{S}{N}</katex-inline>：信噪比</p>
<p>[!Note]</p>
<ul>
<li>计算时注意“二进制”、“十六进制”等字眼，是波特值的含义，则要在v和C中选出最小的</li>
<li>分贝值的大小为 <katex-inline>d=10log_{10}(\frac{S}{N})</katex-inline>，注意转换</li>
</ul>
</blockquote>
<h3>信道复用</h3>
<ol>
<li>频分复用 FDM：不同用户用不同频率的信道，<strong>限于模拟信号</strong></li>
<li>时分复用 TDM：分时服务用户</li>
<li>波分复用 WDM：（光的）波长</li>
<li>！码分复用 CDM
<ul>
<li>码片<katex-inline>m_i</katex-inline>：分给每个站码片 <katex-inline>m_i</katex-inline>，码片之间正交</li>
<li>码片向量：码片 <katex-inline>m_i</katex-inline> 的1为1，0为-1</li>
<li>站点发送：比特1为码片向量，比特0为码片销量负值</li>
<li>站点接收：与自身码片向量相乘，除以码片长度</li>
</ul></li>
</ol>

<h2>I.数据链路层概述</h2>
<h3>相关名词</h3>
<ol>
<li>链路：从一个节点到相邻节点的通信信道，中间==无交换节点==</li>
<li>数据链路：链路+链路层协议</li>
<li>帧：数据链路层传输的数据单元 PDU</li>
</ol>
<h3>！服务</h3>
<ol>
<li>无确认的无连接服务：不需要建立连接，不需要确认，如以太网</li>
<li>有确认的无连接服务：不需要建立连接，需要确认，如无线局域网</li>
<li>有确认的面向连接服务：需要建立连接，需要确认，如PPP</li>
</ol>
<h3>设备</h3>
<h4>交换机（多接口网桥）</h4>
<ul>
<li>
<p>工作流程</p>
<ul>
<li>
<p>自学习：收到帧，发现转发表中没有此帧的源MAC和目的MAC，记录MAC和对应接口，并<strong>广播</strong>到==其他==所有接口</p>
</li>
<li>转发：收到帧，转发表中有目的MAC表项，转发到对应接口</li>
</ul>
</li>
<li>
<p>工作模式</p>
<ul>
<li>直通交换：只检查帧首目的MAC地址，直接转发</li>
<li>存储转发：存储到内存中进行检错，错则丢，无损则转发</li>
</ul>
</li>
<li>特点
<ul>
<li>隔离冲突域：星型一对一</li>
<li>不隔离广播域：广播帧都会被转发</li>
</ul></li>
</ul>

<h4>透明传输</h4>
<blockquote>
<p>传输的数据不受特殊字符的影响</p>
</blockquote>
<ul>
<li>字符填充：在数据中插入转义字符，如HDLC的ESC(11111101)</li>
<li>字符计数：在帧首部加入帧长度</li>
</ul>
<h4>流量控制</h4>
<blockquote>
<p>控制==发送方==发送速率，防止接收方缓存溢出</p>
</blockquote>
<ul>
<li>OSI体系中，数据链路层有流量控制的功能</li>
<li>TCP/IP体系中，流量控制由==传输层==负责</li>
</ul>
<h4>差错检测</h4>
<blockquote>
<p>通过确认重传、CRC检测帧中的错误</p>
</blockquote>
<ul>
<li>
<p>CRC：检测帧内位错，将帧看成多项式，除以生成多项式，余数作为校验码</p>
</li>
<li>确认重传：帧丢失，超时重传
<ul>
<li>通信质量好的线路，仅进行CRC检测，重传由上层协议处理</li>
<li>通信质量差的线路，进行确认重传</li>
</ul></li>
</ul>
<h2>II.组帧</h2>
<blockquote>
<p>功能：将网络层递交的分组封装成帧</p>
<p>问题：帧定界、帧同步、透明传输</p>
</blockquote>
<ol>
<li>
<p>字符计数法：帧首部添加==计数字段==记录该帧的字节数</p>
</li>
<li>
<p>字节填充法：</p>
<ul>
<li>添加SOH、EOT标识帧头帧尾</li>
<li>数据段中存在”SOH、EOT、ESC“字符，前面添加ESC进行转义</li>
</ul>
</li>
<li>
<p>（==HDLC==）零比特填充法：</p>
<ul>
<li>使用01111110标志帧开始和结束</li>
<li>数据字段中每连续5个”1“后自动添加一个”0“</li>
</ul>
</li>
<li>违规编码法：使用数据传输方式中不用的编码标识首尾</li>
</ol>
<h2>III.差错控制</h2>
<h4>检错编码</h4>
<ul>
<li>
<p>奇偶检验码：数据中”1“的个数</p>
</li>
<li>循环冗余码CRC
<ul>
<li>约定 <katex-inline>G(x) = x^{n_k}+x^{n_{k-1}}+···+x^{n_1}</katex-inline></li>
<li>冗余码计算：在源数据后加 <katex-inline>G(x)</katex-inline> 中 <katex-inline>Max(x_{n_k}、x_{n_{k-1}}···x_{1})</katex-inline> 位，进行除法计算</li>
</ul></li>
</ul>
<h4>纠错编码</h4>
<ul>
<li>
<p>海明码距 <katex-inline>d_{min}</katex-inline></p>
<ul>
<li>检错数量 <katex-inline>r = d_{min}-1</katex-inline></li>
<li>校正错误数量 <katex-inline>r = (d_{min}-1)/2</katex-inline></li>
</ul>
</li>
<li>海明码：见车爹PPT</li>
</ul>
<h2>IV.流量控制和可靠传输</h2>
<h4>流量控制</h4>
<blockquote>
<p><strong>流量控制指由==接收方控制发送方==的发送速率。</strong>  </p>
<ol>
<li>
<p>数据链路层控制的相邻结点之间的流量；传输层控制端到端流量</p>
</li>
<li>数据链路层控制方法：接收方<u>是否返回ACK</u>控制；传输层控制方法：接收方在ACK设置窗口值调整发送方的发送窗口</li>
</ol>
</blockquote>
<h4>可靠传输</h4>
<blockquote>
<p><strong>可靠传输是指发送方数据能被接收方正确接收</strong></p>
<ol>
<li>有线网络数据链路层不负责可靠运输</li>
<li>无线网络数据链路层负责可靠运输</li>
</ol>
</blockquote>
<ol>
<li>
<p>停止等待协议(S-W)</p>
<ul>
<li>
<p>一次只发送一帧</p>
</li>
<li>超时重传</li>
<li>一位比特编号</li>
<li>设置帧缓冲区用于重传</li>
</ul>
</li>
<li>
<p>后退N帧协议(GBN)</p>
<ul>
<li>
<p>发送方在发送窗口内连续发送</p>
</li>
<li>
<p>接收方发现丢失一帧，后面全无效</p>
</li>
<li>
<p>接收方可累计确认，只确认最新连续的一位</p>
</li>
<li>发送方接收到ACK后，可直接将窗口后滑</li>
</ul>
</li>
<li>选择重传(SR)
<ul>
<li>发送方在发送窗口内连续发送</li>
<li>接收方必须每帧都发送确认</li>
<li>接收方检测到错误帧就发送NAK，要求==立即重传==要求的帧</li>
</ul></li>
</ol>
<blockquote>
<p>[!Tip]</p>
<p>注意题目中的帧数和帧序号<strong>比特数</strong>区别</p>
<p>帧序号比特数k：<katex-inline>2^k - 1 &gt;= n</katex-inline></p>
</blockquote>
<h2>V.介质访问控制</h2>
<h3>随机访问控制</h3>
<h4>ALOHA协议</h4>
<ol>
<li>
<p>纯ALOHA协议</p>
<p>发送方：随机发送数据帧，发送成功则等待下一帧，发送失败则等待<strong>随机时间</strong>后重传，直到发送成功</p>
</li>
<li>
<p>时隙ALOHA协议</p>
<p>发送方：等待下一个时隙发送数据帧，发送成功则等待下一帧，发送失败则等待<strong>下一个时隙</strong>后重传，直到发送成功</p>
</li>
</ol>
<h4>CSMA协议</h4>
<ol>
<li>
<p>1-坚持CSMA协议</p>
<p>发送方：要发送信号时，<strong>持续监听</strong>信道，信道空闲则发送数据帧，直到发送成功</p>
</li>
<li>
<p>非坚持CSMA协议</p>
<p>发送方：要发送信号时，若信道忙则等待<strong>随机时间</strong>后再次监听信道，信道空闲则发送数据帧，直到发送成功</p>
</li>
<li>
<p>p-坚持CSMA协议</p>
<p>发送方：要发送信号时，若信道忙则等待<strong>随机时间</strong>后再次监听信道，信道空闲则以概率p发送数据帧，以概率1-p继续等待</p>
</li>
</ol>
<h4>CSMA/CD协议</h4>
<blockquote>
<p>总线型有线网络</p>
<p>半双工通信</p>
</blockquote>
<img src="https://cdn.aweip.com/markdown/202411021628211.png" alt="image-20241102160536375" style="zoom:33%;" />
<ol>
<li>
<p>发送阶段：检测冲突</p>
<ul>
<li>
<p><katex-inline>争用期 t=2τ</katex-inline> ：代表信号在端到端往返的最大时间，若在此时间内没有检测到冲突，则发送成功</p>
</li>
<li><katex-inline>最小帧长L_{min} = 2τ*v</katex-inline>：保证在发生冲突时，发送方能检测到冲突；
10Mbps以太网：<katex-inline>t= 51.2μs</katex-inline>，<katex-inline>L_{min} = 512bit =64B</katex-inline></li>
</ul>
</li>
<li>
<p>！冲突阶段：截断二进制</p>
<ul>
<li>二进制指数退避算法：<katex-inline>R = rand(0,1,···,2^k-1)</katex-inline>，<katex-inline>k=min(n,10)</katex-inline>，<katex-inline>n</katex-inline>为冲突次数</li>
<li><katex-inline>重传推迟时间t_{backoff} = R*2τ</katex-inline></li>
<li>发送失败：当<katex-inline>n &gt;= 16</katex-inline>时，发送失败</li>
</ul>
</li>
</ol>
<h4>！CSMA/CA协议</h4>
<blockquote>
<p>无线局域网</p>
</blockquote>
<p><img src="https://cdn.aweip.com/markdown/202411022055051.png" alt="58e956f8659f871bdfb62cad6b56a6f5" /></p>
<ol>
<li>发送阶段
<ul>
<li>源站检测信道空闲，等待==DIFS==长度的时间准备发送</li>
<li>源站检测信道空闲，使用==随机避让算法==延迟</li>
</ul></li>
<li>[可无此阶段]信道预约阶段
<ul>
<li>源站<strong>广播</strong>发送==RTS==报文</li>
<li>目的站等待==SIFS==后，发出==CTS==，通信范围接收到此帧的其他站保持静默（处理隐蔽站问题）</li>
</ul></li>
<li>数据传输阶段
<ul>
<li>源站接收到CTS，等待SIFS后开始发送</li>
<li>目的站接收完数据后，等待SIFS后发送ACK帧回应直到源站接收</li>
<li>此阶段对于其他站为NAV（信道忙）时间</li>
</ul></li>
</ol>
<blockquote>
<ul>
<li>
<p>IFS（InterFrame Space）:帧间间隔</p>
</li>
<li>
<p>DIFS：分布式协调IFS，只在源站侦测到空闲后触发</p>
</li>
<li>
<p>SIFS：短IFS，在任意类型帧间触发</p>
</li>
<li>
<p>RTS（Request To Send）：请求发送控制帧</p>
<ul>
<li>
<p>源地址 + 目的地址</p>
</li>
<li>本次通信所需时间：SIFS + CTS + SIFS + 数据帧 + SIFS + ACK</li>
</ul>
<p>即对面接收完RTS开始，到己方接收完ACK结束</p>
</li>
<li>
<p>CTS（Clear To Send）：允许发送控制帧</p>
<ul>
<li>
<p>给源站明确的发送指令</p>
</li>
<li>
<p>指示其他站在预约期内保持静默</p>
</li>
<li>预约期：SIFS + 数据帧 + SIFS +ACK</li>
</ul>
<p>即对面接收完CTS开始，到对面接收到ACK结束</p>
</li>
<li>
<p>NAV（Network Allocation Vector）</p>
<ul>
<li>
<p>预约时间/信道被分配时间</p>
</li>
<li>在CTS中标明，NAV = SIFS + 数据帧 + SIFS + ACK</li>
</ul>
</li>
<li>
<p>随机避让算法</p>
<ul>
<li>基本退避时间 <katex-inline>2τ</katex-inline></li>
<li>退避计时器在第k次：<katex-inline>R=rand(0,1,···，2^{k+2}-1)，k&lt;=6</katex-inline> </li>
<li>退避时间 <katex-inline>2τ*R</katex-inline></li>
</ul>
</li>
</ul>
</blockquote>
<h3>轮询访问</h3>
<p><strong>令牌传递协议</strong></p>
<ol>
<li>源站按环路连接，令牌轮流传递；</li>
<li>
<p>一个站点拥有令牌后</p>
<ul>
<li>
<p>无数据发送，则<strong>立即</strong>传给下一站</p>
</li>
<li>有数据发送，将令牌中插入数据发送，每次只能发送一帧；</li>
</ul>
</li>
<li>数据帧在环路循环转发，目的站收到后复制再继续转发；</li>
<li>源站收到后检验帧，出错则重发，否则生成新令牌并传递给下一站。</li>
</ol>
<h2>VI.局域网</h2>
<h3>概览</h3>
<ol>
<li>
<p>介质访问控制方法：CSMA/CD、令牌总线、令牌环</p>
</li>
<li>
<p>局域网拓扑：以太网、令牌环、FDDI</p>
</li>
<li><strong>IEEE802</strong>定义：
<ul>
<li>逻辑链路控制（LLC）：无确认无连接、带确认无连接（帧加序号）、面向连接、高速传送、寻址、竞争处理</li>
<li>介质访问控制（MAC）：组帧、差错控制、透明传输</li>
</ul></li>
</ol>
<h3>以太网V2/802.3</h3>
<blockquote>
<p>结构：逻辑总线型、物理星型（一交换机连多终端）</p>

<h2>VII.广域网</h2>
<h3>PPP协议</h3>
<blockquote>
<p>用户与ISP的通信协议</p>
<p>数据层面：不可靠、无序号和确认</p>
<p>控制层面：面向连接</p>
<p>只保证CRC检错实现<strong>无差错接收</strong></p>
<p>面向==字节==、全双工</p>
</blockquote>
<ul>
<li>
<p>组成部分</p>
<ul>
<li>链路控制协议LCP：配置测试链路连接，协商参数</li>
<li>网络控制协议NCP：对接兼容多种网络层协议</li>
<li>组帧方法（规范）</li>
</ul>
</li>
<li>
<p>！PPP帧</p>
<ul>
<li>结构
<img src="https://cdn.aweip.com/markdown/202411071640520.png" alt="image-20241107164016223" style="zoom:40%;" /></li>
<li>
<p>首尾标志字段F：0X7E，定界符（与V2帧相比，有尾定界符）</p>
<ul>
<li>同步传输：零比特填充法，防止0x7E（01111110）在内部出现</li>
<li>异步传输：转义字符0x7D</li>
</ul>
</li>
<li>地址字符A：0xFF，无用</li>
<li>控制字符C：0x03，无用</li>
<li>协议字符P：0x0021-&gt;IP数据报；0xC021-&gt;LCP数据</li>
<li>数据载荷：0~1500B（不用CSMA/CD，无需最小帧长）</li>
<li>帧检验FCS：CRC检验冗余码</li>
</ul>
</li>
<li>
<p>连接过程</p>
<pre><code class="mermaid">flowchart TD
A[链路静止] --&gt; |物理层链路建立| B[链路建立]

B --&gt; |LCP配置协商|C[鉴别]
C --&gt; |鉴别失败|D[链路终止]
D --&gt; |LCP链路终止|A
C --&gt; |鉴别成功|E[网络层协议]
E --&gt; |NCP配置协商|F[链路打开]
F --&gt; |链路故障或终止|D

<h3>DHCP 协议</h3>
<h3>ICMP 网际控制协议</h3>
<blockquote>
<ul>
<li>IP报文</li>
<li>网络层数据报转发时状态信息交互</li>
</ul>
</blockquote>
<ul>
<li>
<p>ICMP差错报告报文</p>
<ul>
<li>终点不可达：路由器/主机==不能交付报文==时向源发送</li>
<li>源点抑制：路由器/主机因为==拥塞==丢弃报文时向源发送</li>
<li>超时：路由器收到TTL==为0==的报文时向源发送，若收不到全部分片则全部丢弃</li>
<li>参数问题：路由器/主机收到==首部字段校验和错误==时丢弃报文，并向源发送</li>
<li>改变路由（重定向）：路由器向源发送，告知源有更好的路由</li>
</ul>
<blockquote>
<p>不发送ICMP差错报告的情况</p>
<ul>
<li>ICMP差错报告报文，不发送ICMP差错报告</li>
<li>特殊地址不发（广播、回环）</li>
<li>多分片报文只发送一次，后续分片不发</li>
</ul>
</blockquote>
</li>
<li>
<p>ICMP询问报文</p>
<ul>
<li>回送请求和应答：PING（应用层）</li>
<li>时间戳请求和应答：Traceroute（网络层）</li>
<li>地址掩码请求和应答</li>
<li>路由器请求和通告</li>
</ul>
</li>

<p>由于接口标识可对MAC地址进行编码，所以可以通过IPv6地址直接找到MAC地址，==省去ARP协议==</p>
</blockquote>
</li>
<li>
<p>V4和V6地址转换</p>
<ul>
<li>双栈：同时支持V4和V6</li>
<li>隧道：V4数据报封装在V6数据报中</li>
<li>NAT64：V6数据报封装在V4数据报中</li>
</ul>
</li>
</ul>
<h2>IV.路由协议</h2>
<h3>RIP协议</h3>
<blockquote>
<ul>
<li>应用层，UDP封装</li>
<li>基于距离向量</li>
<li>路由器到直连网络的距离定义为1</li>
<li>只和==相邻==路由器交换自己的<strong>路由表</strong></li>
<li>周期30s交换更新路由表，180秒无报文则此路由失效</li>
</ul>
</blockquote>
<ul>
<li>
<p>收敛：每个路由器都知道到达本自治系统AS内各网络的最短距离和下一跳路由器</p>
</li>
<li>
<p>计算流程：</p>
<ul>
<li>
<p>A向相邻的B发送路由表a</p>
</li>
<li>
<p>B将a中所有距离条目加上与A的距离，下一跳改为A</p>
</li>
<li>和自身路由表进行比较，选最短的</li>
</ul>
<img src="https://cdn.aweip.com/markdown/202411122025517.png" alt="image-20241112202540416" style="zoom:50%;" />
</li>
<li>存在问题：网络N1突然失效，相邻路由器更新成16不可达之后，被相邻其他无法获取到N1状态的路由器路由表影响，16不可达被覆盖为可达。直到多次后才能确认不可达。</li>
</ul>
<h3>OSPF协议</h3>
<blockquote>
<ul>
<li>
<p>网络层，IP数据报</p>
</li>
<li>基于链路状态（量化为代价）</li>
<li>支持CIDR</li>
<li>有鉴别，保证安全</li>
<li>链路状态有32位序号，越大越新</li>
</ul>
</blockquote>
<ul>
<li>
<p>代价计算</p>
<katex>
cost = 100Mbps/链路带宽</katex>
<p>cost大于1则保留整数，小于1则记为1</p>
</li>
<li>
<p>链路状态表：相邻路由 + 代价</p>
</li>
<li>
<p>区域划分：为适配大规模网络，OSPF将一个自治系统AS再划分为多个==区域==，限制洪泛范围，减少通信量，但OSPF更复杂了</p>
<ul>
<li>==主干==区域连接若干区域</li>
<li>主干路由器：主干区域内的路由器，包含边缘</li>
<li>区域内路由器：只在区域内，不连接主干路由器</li>
<li>区域边界路由器：属于主干路由器，与其他区域连接</li>
</ul>
</li>
</ul>
<h4>链路建立和维护</h4>
<ol>
<li>
<p><strong>问候（hello）</strong></p>
<ul>
<li>建立邻居表</li>
<li>发送周期10s，若40s未收到某方hello则视为其已经不可达</li>
</ul>
</li>
<li>
<p><strong>链路状态更新分组（LSU）</strong></p>
<ul>
<li>
<p>链路状态通告（LSA）：<strong>直连网络 + 邻居路由器</strong>的链路状态信息</p>
</li>
<li>
<p>==可靠==的<strong>洪泛</strong>发送</p>
<blockquote>
<p>可靠：需要收到的路由器发送==链路状态确认==报文</p>
<p>洪泛：向所有相邻路由器发送，它们收到后继续转发给相邻</p>
</blockquote>
</li>
</ul>
</li>
<li>
<p><strong>链路状态数据库（LSDB）</strong></p>
<ul>
<li>每一个路由器都存储，记录链路状态通告（LSA）</li>
<li>通过洪泛使得网络中所有LSDB一致</li>
</ul>
</li>
</ol>

<h2>V.IP多播</h2>
<h3>基本概念</h3>
<img src="https://cdn.aweip.com/markdown/202411131618627.png" alt="image-20241113161814463" style="zoom:40%;" />
<ul>
<li>一对多</li>
<li>多端口转发</li>
<li>IPv4中使用D类多播地址：1110****.*.*.*
<ul>
<li>==224==.0.0.0 ~ ==239==.255.255.255</li>
<li>一个D类地址代表一个<strong>多播组</strong></li>
</ul></li>
</ul>
<h3>！局域网硬件多播</h3>
<blockquote>
<p>解决本地局域网内多播数据包分发问题</p>
</blockquote>
<ol>
<li>IPv4地址映射<u>多播MAC地址</u>
<ul>
<li>多播MAC号：前25比特相同，01：00：5E：0<strong><strong> </strong></strong>：···
<img src="https://cdn.aweip.com/markdown/202411131632419.png" alt="image-20241113163231347" style="zoom:50%;" /></li>
<li>后23位来自多播IP地址后23位</li>
<li>由于D类前4位为1110，后23位映射到多播MAC，有32-4-23=5位没映射到MAC地址上，使得一个MAC地址对应2^{5}=32个IP上</li>
<li>在网络层还需要过滤非目的IP的报文（IP和MAC双匹配）</li>
</ul></li>
</ol>
<h3>因特网多播</h3>
<blockquote>
<p>解决多播组设备寻址问题</p>
</blockquote>
<h4>IGMP</h4>
<blockquote>
<ul>
<li>
<p>多播路由器运行IGMP，监视本局域网内多播组成员变化</p>
</li>
<li>路由器不知道多播组成员数量和网络分布情况</li>
</ul>
</blockquote>
<ul>
<li>IGMP报文类型
<ul>
<li>成员报告报文：设备-&gt;多播路由器，加入</li>
<li>成员查询报文：多播路由器-&gt;设备，是否存活</li>
<li>离开组报文：设备-&gt;多播路由器，直接退出</li>
</ul></li>
</ul>
<h4>多播路由选择协议</h4>
<ul>
<li>目标：为每个多播组建立多播转发树，使报文只转发一次</li>
<li>IP多播组沿多播转发树洪泛，能传到所有拥有多播成员的多播路由器</li>
<li>多播路由器再进行硬件多播</li>

<h2>VI.移动IP</h2>
<ul>
<li>
<p>原因：移动设备在某个网络下获得了IP地址</p>
<ul>
<li>
<p>设备在移动状态下需要在不同网域下使用网络</p>
</li>
<li>正在提供服务的服务器也需要定位到此设备，移动设备IP不能改变</li>
</ul>
</li>
<li>
<p>解决方法：代理</p>
<ol>
<li>设备在归属地获得永久（归属）地址，上级路由称为归属代理</li>
<li>设备移动到其他网络下</li>
<li>设备使用代理发现协议，在外地网络注册，并提供永久地址和归属代理地址</li>
<li>外地代理通过以上信息与归属地代理建立IP隧道</li>
<li>归属地代理==接收==到数据后，转发给外地代理，外地代理转发给移动设备</li>
<li>移动主机==发送==数据时，交给外地代理直接转发，不需要送给归属代理</li>
</ol>
<img src="https://cdn.aweip.com/markdown/202411131713437.png" alt="image-20241113171312326" style="zoom:50%;" />
</li>
</ul>
<h1>第五章 传输层</h1>
<h2>I.概述</h2>
<blockquote>
<p>物理层+数据链路层+网络层 -&gt; 主机到主机通信</p>
<p>传输层 -&gt; 进程到进程通信</p>
</blockquote>
<h3>端口号</h3>
<blockquote>
<p>区分计算机类进程的数据报文</p>
<p>同设备内一个端口只能建立一个连接</p>
</blockquote>
<ul>
<li>长度：2B</li>
<li>范围：0 ~ 65535（<katex-inline>2^{16}-1</katex-inline>）</li>
<li>分类
<ul>
<li>熟知端口：0~1023</li>
<li>登记端口：1024~49151</li>
<li>临时端口：49152~65535</li>
</ul></li>
</ul>
<h3>复用分用</h3>
<ul>
<li>
<p>复用</p>
<ul>
<li>TCP/UDP 复用：理解为应用报文打包</li>
<li>IP复用：传输层报文打包为IP报文</li>
</ul>
</li>
<li>分用：理解为解包并分流到各自应用进程</li>
</ul>
<img src="https://cdn.aweip.com/image-20241116103731026.png" alt="image-20241116103731026" style="zoom:50%;" />
<h2>II.UDP</h2>
<blockquote>
<p>无连接不可靠，不使用流量控制和拥塞控制</p>
<p>检查到错包就丢弃</p>
<p>支持广播、多播、单播</p>
<p>伪首部序号为17</p>
</blockquote>
<h3>UDP首部</h3>
<table>
<thead>
<tr>
<th>源端口</th>
<th>目的端口</th>
<th>长度</th>
<th>校验和</th>
</tr>
</thead>
<tbody>
<tr>
<td>2B</td>
<td>2B</td>
<td>2B</td>
<td>2B</td>
</tr>
</tbody>
</table>
<ul>
<li>源端口：可选，不需要时全0</li>
<li>目的端口：</li>
<li>长度：首部+数据，最小8（首部长度）</li>
<li>校验和：需要加上12B伪首部</li>
</ul>
<h2>III.TCP</h2>
<blockquote>
<p>面向连接 可靠</p>
<p>对==报文段==进行确认</p>
<p>面向字节流</p>
<p>伪首部中序号为6</p>
</blockquote>
<h3>TCP首部</h3>
<img src="https://cdn.aweip.com/image-20241117200631937.png" alt="image-20241117200631937" style="zoom:50%;" />
<ul>
<li>序号：32b，代表本报文段第一个字节序号</li>
<li>确认号：32b，指出期望收到对方下一个TCP报文段的数据载荷的第一个字节的序号</li>
<li>数据偏移：4b，数据报长度，单位4B</li>
<li>保留：6b，无用置0</li>
<li>短状态：1有效
<ul>
<li>URG：紧急报文，首先传送</li>
<li>ACK：为1则确认字段有效</li>
<li>PSH：尽快交付，不保留在缓冲区</li>
<li>RST：复位，释放连接再重新连接</li>
<li>SYN</li>
<li>连接请求报文：SYN=1，ACK=0</li>
<li>连接确认报文：SYN=1，ACK=1</li>
<li>FIN：终止位，代表要求释放连接</li>
</ul></li>
<li>窗口：16b，代表接收方所允许的对方发送的数据量（rnwd)</li>
<li>校验和：12b，伪首部+首部+数据载荷计算反码算数运算求和</li>
<li>紧急指针：16b，URG=1时才有效，指明紧急数据的<strong>长度</strong>，单位1B</li>
</ul>
<h3>建立连接</h3>
<h4>三次挥手</h4>
<img src="https://cdn.aweip.com/24d2e9bc13930dbe39a443b1f728e68.jpg" alt="24d2e9bc13930dbe39a443b1f728e68" style="zoom:50%;" />
<ul>
<li>第一次：SYN=1,ACK=0，==SYN占用一个序号==</li>
<li>第二次：SYN=1,ACK=1，==SYN占用一个序号==</li>
<li>第三次：ACK=1，可带可不带数据，不带数据则不占用序号</li>
</ul>
<blockquote>
<p>[!TIP]</p>
<ul>
<li>采用“三报文握手”而不是“两报文握手”来建立TCP连接，是为了<strong>防止已失效的TCP连接请求报文段</strong>突然又传送到了TCP服务器进程，因而导致错误。</li>
<li>左边：
<ul>
<li>CLOSED</li>
<li>SYN-SENT</li>
<li>ESTABLISHED</li>
</ul></li>
<li>右边：
<ul>
<li>CLOSED</li>
<li>LISTEN</li>
<li>SYN-RCVD</li>
<li>ESTABLISHED</li>
</ul></li>
</ul>
</blockquote>
<h4>四次挥手</h4>
<p><img src="https://cdn.aweip.com/image-20241117225138826.png" alt="image-20241117225138826" /></p>
<ul>
<li>第一次：FIN=1,ACK=1，==FIN占用一个序号==</li>
<li>第二次：ACK=1，继续传送数据</li>
<li>第三次：FIN=1,ACK=1，数据传送完，使用FIN表示准备断开</li>
<li>第四次：ACK=1，对方收到后断开，己方等待2MSL</li>
</ul>
<blockquote>
<p>[!TIP]</p>
<ul>
<li>等待2MSL是防止第四次丢失，导致对面无法关闭</li>
<li>左边：
<ul>
<li>ESTABLISHED</li>
<li>FIN-WAIT1</li>
<li>FIN-WAIT2</li>
<li>TIME-WAIT</li>
<li>CLOSED</li>
</ul></li>
<li>右边：
<ul>
<li>ESTABLISHED</li>
<li>CLOSE-WAIT</li>
<li>LAST-ACK</li>
<li>CLOSED</li>
</ul></li>
</ul>
</blockquote>
<h3>流量控制</h3>
<blockquote>
<ul>
<li>接收窗口（rwnd)：发送方维持，代表缓冲区能接受的容量</li>
<li>实现端到端的流量控制（两个进程直接），数据链路层是节点之间的流量控制</li>
</ul>
</blockquote>
<p>滑动窗口+持续计时器</p>
<h3>拥塞控制</h3>
<blockquote>
<ul>
<li>
<p>种类</p>
<ul>
<li>
<p>开环控制：初始即设计好一切情况</p>
</li>
<li>闭环控制：引入反馈，边监测边调整</li>
</ul>
</li>
<li>
<p>拥塞窗口（cwnd)：发送方的窗口大小</p>
</li>
<li>发送上限 = min[cwnd, rwnd]</li>
</ul>
</blockquote>
<h4>慢开始</h4>
<ul>
<li>
<p>拥塞窗口cwnd从1开始，每经过一次确认（时隔1TTL）后乘2</p>
</li>
<li>慢开始门限（ssthresh)：到达限制后cwnd进入拥塞避免</li>
</ul>
<h4>拥塞避免</h4>
<ul>
<li>cwnd到达ssthresh后，每次加一</li>
<li>直到发生超时（拥塞）或者收到三次确认报文，进入下一种调整模式</li>
</ul>
<h4>快重传</h4>
<ul>
<li>报文丢失（非拥塞状态）</li>
<li>接受方发送三次确认报文冗余ACK</li>
<li>发送方立即重传对方所需报文段</li>
</ul>
<h4>快恢复</h4>
<blockquote>
<p>收到==三次确认报文==后进行</p>
</blockquote>
<ul>
<li>ssthresh调为当前cwnd一半</li>
<li>cwnd调为当前一半</li>
<li>进入拥塞避免</li>
</ul>
<h1>第六章 应用层</h1>
<h2>I.网络应用模型</h2>
<h3>C/S模型</h3>
<ul>
<li>服务器：总是打开，提供服务，面向任务</li>
<li>客户机：请求服务，面向用户</li>
<li>特点：
<ul>

<h3>P2P模型</h3>
<ul>
<li>对等方（Peer）：任意一对计算机，直接相互通信</li>
<li>可扩展性好</li>
<li>网络健壮性好</li>

<h2>II.动态主机配置协议（DHCP）</h2>
<blockquote>
<p>动态分配地址</p>
<p>基于UDP，主机端口68，服务器67</p>
</blockquote>
<h3>！工作流程</h3>
<ol>
<li>客户端加入：客户端广播<strong>DHCP发现</strong>，源地址全0，目的地址全1</li>

<li>客户端接受此服务器，广播<strong>DHCP请求</strong>，源地址全0，目的地址全1</li>
<li>服务器广播<strong>DHCP确认</strong>，分配IP地址，源地址服务器地址，目的地址全1</li>
</ol>

<h2>III.域名系统（DNS）</h2>

<h3>域名服务器</h3>
<ol>
<li>根域名服务器：被所有本地域名服务器所知</li>
<li>顶级域名服务器：com、cn、site等</li>
<li>权限域名服务器</li>
<li>本地域名服务器</li>
</ol>
<h3>解析过程</h3>
<ul>
<li>
<p>递归查询</p>
<ul>
<li>本地主机向本地域名服务器查询</li>
<li>本地域名服务器向根域名服务器查询</li>
<li>根域名服务器向顶级域名服务器查询</li>
<li>···</li>
</ul>
<blockquote>
<ul>
<li>主机-&gt;本地-&gt;==根域名==-&gt;顶级域名-&gt;权限域名</li>
<li>根域名负载大 ，基本不用</li>
<li><strong>主机和本地域名服务器之间只使用递归查询</strong></li>
</ul>
</blockquote>
</li>
<li>
<p>迭代查询</p>
<ul>
<li>本地主机向本地域名服务器查询</li>
<li>本地域名服务器：</li>
<li>向根域名服务器查询</li>
<li>向顶级域名服务器查询</li>
<li>向权限域名服务器查询</li>
<li>本地域名服务器向主机返回结果</li>
</ul>
</li>
</ul>
<h2>IV.文件传输系统（FTP）</h2>
<blockquote>
<p>交互式访问，允许用户指明==文件类型和格式==</p>
<p>控制连接：端口21，TCP</p>
<p>数据连接：端口20，TCP</p>
<p>会话过程，服务器保留用户状态信息，追踪用户在远程目录树位置</p>
</blockquote>
<h3>控制连接</h3>
<ul>
<li>传输控制信息</li>
<li>会话期间保持打开</li>
</ul>
<h3>数据连接</h3>
<ul>
<li>接收到文件传输请求后，创建数据传送进程和数据连接</li>
<li>传送完毕后关闭</li>
<li>模式
<ul>
<li>主动模式PORT：客户端发送PORT命令和==客户端随机开放端口号<katex-inline>x</katex-inline>==，服务器通过20与<katex-inline>x</katex-inline>连接</li>
<li>被动模式PASV：客户端发送PASV命令，==服务器在本地开放随机端口<katex-inline>y</katex-inline>==，告知客户端</li>
<li>选择权都在客户端上</li>
</ul></li>
</ul>
<blockquote>
<p>网络文件系统NFS</p>
<ul>
<li>FTP：修改服务器上文件，先==全部==下载到本地，修改完再传回</li>
<li>NFS：远程打开文件，在文件特定位置读写修改</li>
</ul>
</blockquote>
<h2>V.电子邮件（Email）</h2>
<h3>组成结构</h3>
<ul>
<li>用户代理UA：<strong>程序</strong>，如QQ邮箱、Outlook软件</li>
<li>邮件服务器：用于发送、接收邮件</li>
<li>邮件发送和读取协议：存取协议</li>
</ul>
<img src="https://cdn.aweip.com/markdown/202411181756805.png" alt="image-20241118175626645" style="zoom:50%;" />
<ul>
<li><strong>现状</strong>：用户通过浏览器使用HTTP协议发送邮件，SMTP只在服务器之间</li>
</ul>
<h3>邮件格式和MIME</h3>
<h4>格式</h4>
<ul>
<li>
<p>信封：从内容自动提取目的人和标题</p>
</li>
<li>内容
<ul>
<li>首部</li>
<li>FROM</li>
<li>To</li>
<li>Subject</li>
<li>主体内容</li>
</ul></li>
</ul>
<h4>MIME</h4>
<p>由于SMTP只能传输7位ASCII码文件，需要MIME进行内容扩展，可以讲图片音视频等转换为7位ASCII，并读取恢复</p>
<h3>！发送协议IMAP</h3>
<blockquote>
<p>SMTP==服务器==端口号：25</p>
</blockquote>
<ol>
<li>
<p>连接建立</p>
<ul>
<li>发送方SMTP服务器（客户端）与接收方SMTP服务器建立TCP连接</li>
<li>接收方服务器发出220服务就绪</li>
<li>客户端发送HELLO+客户端主机名</li>
<li>接收方发送250 OK</li>
</ul>
</li>
<li>
<p>邮件发送</p>
<ul>
<li>客户端发送MAIL FROM+主机名</li>
<li>接收方服务器准备好则发送250 OK</li>
<li>客户端发送RCPT TO+收件人地址</li>
<li>接收方服务器准备好则发送250 OK</li>
<li>客户端发送DATA命令</li>
<li>接收方服务器准备好则发送250 OK</li>
<li>客户端发邮件内容，<CRLF>.<CLRF>代表结束</li>
<li>接收方服务器准备好则发送250 OK</li>
<li>客户端发送QUIT</li>
<li>接受方服务器发送221，==主动断开==</li>
</ul>
<p><img src="https://cdn.aweip.com/markdown/202411181811066.png" alt="image-20241118181130903" /></p>
</li>
</ol>
<h3>接收协议POP3和IMAP</h3>
<ul>
<li>POP3
<ul>
<li>TCP，端口110</li>
<li>工作方式</li>
<li>下载并保留：主机下载完邮件保留在SMTP服务器上</li>
<li>下载并删除：主机下载完邮件删除SMTP服务器的文件</li>
</ul></li>
<li>IMAP
<ul>
<li>允许用户创建文件夹，并移动位置</li>
<li>允许用户只获取邮件部分报文</li>
</ul></li>
</ul>
<h2>VI.万维网WWW</h2>
<h3>URL</h3>
<ul>
<li>
<p>统一资源定位符</p>
</li>
<li>
<p>&lt;协议&gt;://&lt;域名（或IP）&gt;:&lt;端口&gt;/&lt;路径&gt;</p>
<blockquote>
<p>[!TIP]</p>
<p><strong>当浏览器输入URL开始访问(无缓存）：</strong></p>
<ol>
<li>主机向本地域名服务器发出DNS查询</li>
<li>本地域名服务器
<ul>
<li>向根域名服务器查询</li>
<li>向顶级域名服务器查询</li>
<li>向权限域名服务器查询</li>
</ul></li>
<li>本地域名服务器将结果IP返回主机</li>
<li>主机发起TCP连接请求，三次握手后建立连接</li>
<li>主机发出HTTP请求</li>
<li>服务器处理请求，返回HTTP报文</li>
<li>主机收到报文后进行处理</li>
<li>传输结束，四次挥手结束TCP连接</li>
</ol>
</blockquote>
</li>
</ul>
<h3>HTTP</h3>
<blockquote>
<p>无连接，TCP确保可靠连接</p>
<p>无状态，引入Cookie后实现了有状态</p>
</blockquote>
<ul>
<li>
<p>Cookie</p>
<ul>
<li>网站服务器为用户生成Cookie识别码，在服务器中存储用户信息</li>
<li>网站服务器发送给用户的响应报文中有&quot;Set cookie: ****&quot;</li>
<li>用户在自己的Cookie文件中存储此信息</li>
<li>用户下次访问时，在请求报文中添加Cookie值</li>
<li>服务器识别后提供个性化服务</li>
</ul>
</li>
<li>
<p>非持续连接 HTTP1.0：==每个元素==传输都建立一次TCP连接，*<em>2</em>TTL开销**</p>
<img src="https://cdn.aweip.com/markdown/202411181900930.png" alt="image-20241118190049617" style="zoom:50%;" />
</li>
<li>
<p>持续连接 HTTP1.1：建立一次TCP连接后保持，主机发出请求，服务器发送文件</p>
<ul>
<li>
<p>非流水线：一次请求，一个文件</p>
</li>
<li>流水线：可连续发送请求（可视为一次），服务器连续发送多个文件</li>
</ul>
<blockquote>
<p>[!WARNING]</p>
<p>！发送大文件时，需要注意TCP窗口大小（遵循慢启动）</p>
</blockquote>
</li>
