<p>我们在开发的过程中有一些迷，这里记录一下。</p>



<p><strong>前后端分离了怎么用 X-CSRF-Token 来防 csrf</strong>：好像光想着要放 csrf 了，但我们不是前后端分离了吗？<img src="https://s.w.org/images/core/emoji/17.0.2/72x72/1f605.png" alt="😅" class="wp-smiley" style="height: 1em; max-height: 1em;" />后来 CopperKoi 想到前端把 JWT 放在 Authorization Header 不依赖 Cookies 就可以让 csrf 几乎不可能实现。</p>



<p>腾讯的 CodeBuddy 写代码是真的快。我刚开始边翻文档边写代码速度好慢，把文档交给 ai 没过多久路由就都写好了。目前公测没有报告出 ai 代码的问题（只有我灵机一动犯的错）。但是 ai 写代码和我一样有时会出现想当然的错误。</p>

<p><strong>密码怎么传输？</strong>我原本以为在后端 bcrypt 的基础上前端用 sha256 加密之后传输会安全一点，并且将这个设计补充到文档里。但当我问 Deepseek 时，它给出了不同的意见（<a href="https://chat.deepseek.com/share/olhh5465joyqd6rbf8" type="link" id="https://chat.deepseek.com/share/olhh5465joyqd6rbf8">聊天链接</a>）。“sha256 碰撞都来了。”CopperKoi 经过一番研究之后采用了 Deepseek 的建议，传输明文密码，传输过程中的安全由 https 来保障。</p>



<p>没过几天，CopperKoi 的前端也写好了。测试的时候公告的置顶接口出现了一个很奇妙的问题。</p>


<div class="wp-block-image">

<p>接口通过 Params 获取要置顶 / 取消置顶的公告的 uuid，通过 ShouldBindJSON 函数将 body 绑定到模型上。Pinned 布尔值为真则置顶公告，为假则取消置顶。</p>



<p>但是我在测试的时候发现：置顶公告的功能可以跑通，但取消置顶都会报告“参数校验失败”的错误。欸，明明 body 的结构符合要求啊。然后，就出现了惊天大瓜。</p>

<p>六百六十六。我和 CopperKoi 都看呆了。当我们把这个发给<a href="https://www.woooo.tech/zh-cn/" type="link" id="https://www.woooo.tech/zh-cn/">学长</a>时，他给我们分享了这个。</p>



<blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow">
<p>When I send a JSON request with the value true it works, but when I send the same request with false I get the following error.</p>



<p>In summary you need a pointer or custom type to know if the value exists due to Go&#8217;s static nature.</p>
<cite><a href="https://github.com/gin-gonic/gin/issues/814">Bool binding required Bug · Issue #814 · gin-gonic/gin</a></cite></blockquote>



<p>然后学长跟我们介绍了一件事情。</p>



<blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow">
<p>对于一些可以 nil 的字段而言，静态检查十分重要。GORM 的默认主键自增是从 0 开始的，不是从 1 开始，而你初始化系统用的第一个账户大概率是 admin 账户，账户 id 大概率也是 0。如果因为某些 bug，鉴权中间件没绑上 id……所有人都是 admin 了，而且 go 不会有任何错误汇报。</p>
</blockquote>



<p>寄。但我们主键用 uuid 好像把这个坑绕过去了。（不然高低也要踩一回）</p>



<p>给 CopperKoi 提建议的时候我可得劲啦！我给 CopperKoi 提了：将性别从 input 改为单选框、textarea 没有限制宽度可以拉出容器边框、简历显示不出来等等…我们改、测得差不多之后就把代码部署上去让协会里的人公测。</p>



<p>在公测之前，我灵机一动：要不把里面能提的东西都提到 env 里面吧，把参数硬写在代码里不太优雅。然后我看到了 JWT 的 secret…让程序从 env 里面获取 secret。我真是个甜菜！（操作没错，但我的环境变量是用 .env 设置的）</p>

<p>在公测的那天晚上，服务就被学长攻破了。</p>

<p>学长通过 gpt 发现的。</p>



<blockquote class="wp-block-quote is-layout-flow wp-block-quote-is-layout-flow">
<p><code>jwtSecret =[]byte(os.Getenv("secretKey")</code>在包初始化阶段执行，而 env 是在 main.go 里<code>godotenv.Load()</code>才加载；结果 jwtSecret 可能为空字符串。攻击者可用空密钥自行签发 JWT，伪造 <code>role=interviewer</code> 直接接管所有受保护接口。</p>
