<h2 id="实现原理">实现原理
</h2><ol>
<li><strong>内容页保护</strong>：通过检查文章 Front Matter 中的 <code>password</code> 字段。如果存在，将正文内容进行 Base64 编码并隐藏。用户输入密码后，前端计算 SHA256 哈希值与预设密码比对，验证通过后解码并显示内容。</li>
<li><strong>隐私防泄露</strong>：
<ul>
<li><strong>RSS</strong>：在 RSS 订阅源中隐藏加密文章的正文，只显示提示信息。</li>
<li><strong>搜索</strong>：在站内搜索索引中排除加密文章的正文，防止通过搜索结果预览泄露内容。</li>
</ul>
</li>
</ol>
<h2 id="修改步骤">修改步骤
</h2><h3 id="1-修改文章内容页模板">1. 修改文章内容页模板
</h3><p>文件路径：<code>layouts/partials/article/components/content.html</code></p>
<p>主要逻辑是判断 <code>.Params.password</code> 是否存在。如果存在，则渲染一个密码输入框，并将真实内容加密存储在 JS 变量中。</p>

</div><h2 id="注意事项与安全性分析">注意事项与安全性分析
</h2><h3 id="安全性警告">安全性警告
</h3><p><strong>是的，这种方式非常容易被破解。</strong></p>
<p>请务必理解，这是一个<strong>前端保护</strong>方案，它的安全性非常有限，类似于&quot;防君子不防小人&quot;。</p>
<ol>
<li><strong>Base64 不是加密</strong>：我们在模板中使用了 <code>base64Encode</code> 对内容进行编码。Base64 是一种编码方式，不是加密算法。任何懂一点技术的人，查看网页源代码，找到 <code>encodedContent</code> 变量，在浏览器控制台输入 <code>atob(encodedContent)</code> 即可直接看到文章明文。</li>
<li><strong>内容已下发</strong>：虽然页面上看起来需要密码，但实际上文章的全部内容已经下载到了访客的浏览器中，只是被隐藏和编码了。</li>
<li><strong>适用场景</strong>：此方案仅适用于防止普通访客直接查看内容，或者作为一种简单的访问门槛。<strong>绝对不要</strong>用这种方式保护银行账号、密码、私密照片等高度敏感信息。</li>
</ol>
<h3 id="改进思路如果需要更高安全性">改进思路（如果需要更高安全性）
</h3><p>如果需要真正的安全性，必须确保<strong>加密过程发生在构建阶段</strong>，且解密需要密钥（密码）。由于 Hugo 模板语言（Go Templates）本身不内置 AES 等加密函数，要实现真正的加密通常需要：</p>
<ol>
<li><strong>外部脚本预处理</strong>：编写 Python/Node.js 脚本，在 Hugo 构建前运行。脚本读取 Markdown 文件，使用密码对 content 进行 AES 加密，替换原文件内容。</li>
<li><strong>前端解密</strong>：前端引入 <code>crypto-js</code> 库，用户输入密码作为密钥对密文进行解密。</li>
</ol>
<p>目前的方案是 Hugo 原生支持的最简单方案，无需额外的构建步骤。</p>
<h3 id="其他注意事项">其他注意事项
</h3><ul>
<li><strong>HTTPS</strong>：<code>crypto.subtle</code> API 需要在 HTTPS 环境或 localhost 下才能运行。如果你的网站没有部署 HTTPS，解锁功能可能会失效。</li>
</ul><hr />
