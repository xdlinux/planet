<h3><strong>双重</strong> <strong>DES</strong> 为什么不行？（中间相遇攻击）</h3>
<blockquote>
<p><strong>中间相遇攻击</strong>是一种针对双重加密算法的攻击，需要一个已知的明、密文对，本质上，明文在双重加密中被加密产生中间值，密文在双重加密中被解密产生中间值，表查找方式可以用这种方法改进对密钥的蛮力尝试。</p>
</blockquote>
<ul>
<li>已知明文攻击可以成功对付密钥长度为 112 位的 2DES
<ul>
<li><katex-inline>C = E_{K2}(E_{K1}(P)), X = E_{K1}(P) = D_{K2}(C)</katex-inline></li>
<li>用所有可能的密钥加密明文并存储</li>
<li>用所有可能的密钥解密密文，并与存储的X匹配。如果有相等的，那么获得一组可能的密钥对，并用新的明密文对验证。</li>
<li>概率分析：<katex-inline>2^{112}/2^{64}=2^{48}，2^{48}/2^{64}=2^{-16}</katex-inline>，两组明密文对后，正确密钥的概率是<katex-inline>1-2^{-16}</katex-inline>；三组明密对后，正确密钥的概率是<katex-inline>1-2^{-80}</katex-inline></li>
<li>付出数量级为 <katex-inline>O(256)</katex-inline>,比攻击单DES的<katex-inline>O(255)</katex-inline>多不了多</li>
</ul></li>
</ul>
<h3>为什么需要分组密码工作模式</h3>
<p>如果待加密的消息过长，需要将消息分组后，一组一组的使用加密算法，然后输出密文。在这一过程存在两个问题：</p>
<ul>
<li>分组密码不能隐蔽数据模式，即相同的明文分组对应着相同的密文分组，容易受到攻击</li>
<li>分组加密不能抵抗重放、插入和删除攻击等。把分组密码算法用在不同环境时，环境不同要求也不同。</li>
</ul>
<p>为了满足不同要求，需要通过改变分组密码输入和输出的形式，得到分组密码的不同工作模式。</p>

<h3>ElGamal 密码体制</h3>
<ul>
<li>困难问题：离散对数问题</li>
<li>
<p>特点：加密是概率算法—有随机数参与</p>
</li>
<li>
<p>加密过程</p>
<ul>
<li>设m为明文，随机选择整数k，k与p-1互素，计算</li>
<li><katex-inline>c_1 ≡ g^k mod p</katex-inline></li>
<li><katex-inline>c_2 ≡ my^k mod p</katex-inline></li>
<li>密文<katex-inline>c=(c1, c2)</katex-inline></li>
</ul>
</li>
<li>
<p>解密过程</p>
<ul>
<li>收到密文<katex-inline>c=(c1, c2)</katex-inline>后，接收方进行如下计算
<katex>
\begin{array}{l}
c_{2} \cdot\left(c_{1}^{x}\right)^{-1}=m y^{k} \cdot\left(g^{k x}\right)^{-1} 
=m g^{k x}\left(g^{k x}\right)^{-1} \equiv m \bmod p
\end{array}</katex></li>
</ul>
</li>
</ul>
<h2>第十讲 密码学Hash函数</h2>
<h3><strong>Hash</strong> 函数的基本特性、基本设计框架</h3>
<p>任意长度的明文进行变换得到相应的函数值，称为散列值(长度固定)。</p>
<ul>
<li>
<p>用途：消息认证码、数字签名预处理、从口令衍生密钥等。</p>
</li>
<li>
<p>特性：</p>
<ul>
<li>对任意长度输入进行变换，得到固定长度输出</li>
<li>求逆不可行                                                                    抗原像攻击/单向性</li>
<li>对给定 x，很难找到<katex-inline>x’≠x</katex-inline>，使得<katex-inline>h(x’)=h(x)</katex-inline>     抗弱碰撞性</li>
<li>很难找到一对不同的<katex-inline>x, x’</katex-inline>，使得 <katex-inline>h(x’)=h(x)</katex-inline>       抗强碰撞性</li>
</ul>
<blockquote>
<p>满足1-2为单向散列函数，1-3为弱散列函数，1-4 为强散列函数</p>
</blockquote>
<p><img src="https://cdn.aweip.com/image-20230616220452210.png" alt="image-20230616220452210" /></p>
<blockquote>
<p>CVL 为最终的哈希输出</p>
</blockquote>
</li>
</ul>
<h3>生日攻击基本原理</h3>
<ol>
<li>攻击者产生一份合法的明文，再产生232个不同的明文变形，构成一个合法明文组；</li>
<li>生成一份非法明文，构造232个不同的非法明文变形，产生一个非法明文组；</li>
<li>分别对以上两个组产生散列值，在两组明文中找出具有相同散列值的一对明文。如果没有找到，则再增加每组明文变形的数目，直至找到。由 “生日悖论”可知，其成功的概率很大；</li>
<li>于是，攻击者找到了一则与合法明文（至少内容合法）具有相同散列值的非法明文。</li>
</ol>
<h2>第十一讲 消息认证码</h2>
<h3>消息认证码如何设计？基于hash和基于密码的(大致思路)</h3>
<p><strong>基于密码</strong> <strong>hash</strong> <strong>函数的</strong> <strong>MAC**</strong>：<strong>**HMAC</strong></p>
<ul>
<li>不用分组密码，而用 hash 函数来产生 MAC，因为 hash 函数一般都较快 没有出口限制，(分组密码有出口限制)</li>
<li>hash 函数不依赖于密钥，所以不能直接用于 MAC</li>
<li>建议: <katex-inline>KeyedHash = Hash( Key || Message )</katex-inline></li>
</ul>
<p><strong>基于密码的：</strong>采用分组密码（DES）的链接工作（CBC 模式）模式，并把最后分组作为 MAC</p>
<p><strong>看复习PPT，最好能直接画出框图</strong></p>
<p>CMAC：基于密码的消息认证码，框架与 DAA 类似，加密用 AES 和 3DES 实现</p>
